# 07 偏差修复计划（D1~D15）

本文件针对 [06_实现说明与验证报告.md](06_实现说明与验证报告.md) §4 的 15 条 V1 实现偏差，
给出**可执行的修复方案、改动点、验收标准与批次**。架构与功能契约仍以
[02](02_架构设计规格.md) / [03](03_功能设计规格.md) 为准。

- 输入基线：V1 RTL（2026-11-15），Verilator lint 干净，41/41 用例通过
- 原则：**先补集成面与可签核项（P0），再补功能（P1），最后做性能重构（P2）**；
  每一批都必须保持现有 41 个用例与 fp32 495k 对拍全绿，新增能力按"新用例先失败后通过"推进
- 规模标记：**S**（单文件局部改动）、**M**（跨 2~3 个单元 + 新用例）、**L**（新增单元/协议层，需架构评审）

## 2. V1.1：流程与可观测性（不改数据通路）

### D15 门级综合（P0，M）

**现状**：Yosys 0.52 的 SV 前端不支持 `tpu_pkg` 中 `return <expr>` 式 function，
以及 `always_ff` 块内的局部变量声明，`synth` 直接报错，因此面积/频率仍为预算值。

**方案（二选一，优先 A）**
- **A. `sv2v` 预转换**：`sv2v rtl/*.sv > build/synth/tpu_top.v`，再 `read_verilog` 给 Yosys。
  `sv2v` 会把 `return` 展开成 `begin ... end` 赋值、把块内声明搬到模块级。
- **B. 改写代码风格**：把 4 个 fp32 函数与 `blk_bytes/w_shift` 改成 Verilog-2001 赋值式
  （`f = ...; if (...) f = ...;`）。改动虽机械但涉及数值代码，必须重跑 fp32 495k 对拍。

**改动点**
- 新增 `scripts/synth.sh`：`sv2v`（或直接 `read_verilog -sv`）+ `hierarchy -top tpu_top`
  + `proc; opt; memory; opt; techmap; abc -g LUT6; stat`，输出 `build/synth/area.rpt`。
- 目标工艺先用通用门（`synth_generic`）出 LUT/FF 计数，再按需接 `synth_xilinx` 估 DSP/BRAM。
- 记账口径写回 02 文 §8 的表格。

**验收**
- `scripts/synth.sh` 一次跑通，生成 cell 统计；LUT/FF 不超过 02 文预算 ±30%；
- 综合网表与 RTL 用 `scripts/lint.sh` + 41 个用例回归（门级仿真可后置）。

**风险**：`sv2v` 对 unpacked array 端口（`act_idx[MCOLS]`）支持有限；若不支持，
把该端口打包成 `logic [MCOLS*11-1:0]` 再用 generate 展开，RTL 行为不变。

### D13 后门隔离（P1，S）

**现状**：`act_h_*` / `tm_h_*` 与功能端口并列，综合后会留下不可驱动的输入。

**方案**：在 `tpu_top` 内用 `` `ifdef TPU_SIM `` 包住后门逻辑；新增
`sim/tpu_sim_top.sv` 已负责把后门接到测试平台，因此只需保证综合时未定义该宏。
同时把 `act_h_we | q_act_we` 与 `tm_h_we | mxu_tm_we` 的或逻辑一并条件化。

**验收**：`scripts/synth.sh` 的网表端口列表中不含 `act_h_*`/`tm_h_*`；
仿真回归仍全绿（`sim` 构建默认加 `-DTPU_SIM`）。

### D14 `DBG_STATE` 归并（P3，S）

**方案**：最小改动为 `assign dbg_state = (state == S_FETCH2) ? S_FETCH : state;`，
让软件只看到 0~7；`S_FETCH2` 仍在内部存在（取指打拍）。若后续要彻底合并，
把 `FETCH` 改成"发地址—收数据"两拍同一状态的两个子相位。

**验收**：新增 CSR 检查用例，在整个 RUN 期间轮询 `DBG_STATE` 不出现 8；
03 文 §5.1 的说明改为"内部存在但不对外暴露"。

### D12 `STALL_MEM` 计数（P2，S）

**现状**：零延迟存储器模型下没有"未就绪"概念，计数器恒 0。

**方案**：给 `tpu_mxu` 的权重/激活读口加 `*_valid` 输入（由存储器模型或 AXI 壳驱动）；
在 `MX_WR → MX_CALC` 之间插入等待态，当 `!w_valid || !act_valid` 时 `stall_cnt++`，
并通过端口上报顶层。零延迟模型恒 `valid=1`，因此不影响既有节拍。

**验收**：在 `tpu_mem_model` 加可配置延迟（如 3 拍），测出 `STALL_MEM == 期望拍数`；
延迟为 0 时计数器保持 0，41 个用例节拍与结果不变。

## 3. V1.2 / V1.3：集成协议与功能补全

> 本节 D8/D9/D10/D7 属 **V1.2**；D11 与 D2/D3/D4 属 **V1.3**（见 §5 的批次表）。

### D8 AXI4-Lite 从口（P0，M）

**现状**：`cfg_we/cfg_re/cfg_addr/cfg_wdata/cfg_rdata` 直接引出。

**方案**：新增 `rtl/tpu_axil.sv`，实现标准 AXI4-Lite（AW/W/B/AR/R 五通道）：
- 单 outstanding，写响应在收到 W 且地址有效后一拍返回；
- `cfg_re` = `arvalid && arready`，`rdata` 打一拍与 `rvalid` 同拍；
- 非法地址返回 `SLVERR`（映射到 `STATUS.AXI_ERR` 的置位源）；
- 地址窗口 4 KiB（`cfg_addr = awaddr[11:0]`）。

**改动点**：`tpu_top` 例化该壳（或作为独立顶层 `tpu_top_axil`），`tpu_sim_top`
继续直连寄存器侧，保证既有 tb 不变。

**验收**：新增 `sim/tb_axil.cpp` 或用 Verilator 的 AXI VIP 做 AW/W/B、AR/R 握手；
写 `CTRL`/读 `ID`/越界访问三类用例；`STATUS.AXI_ERR` 能置位。

### D9 AXI4 master（P0，L）

**现状**：`mem_*` 为 32 bit 地址 + 64 B/拍 + 8 B 写掩码。

**方案**：新增 `rtl/tpu_axi_mst.sv`：
- 512 bit 数据（64 B/beat），读/写各 32 深 outstanding（预算），4 bit ID；
- `tpu_top` 的 `mem_raddr/mem_rdata` 语义改为"读请求/读返回"，`mem_rdata` 加 `rvalid/rlast`；
- `BRESP/RRESP != OKAY` → `E_AXI_DECERR(0x07)` / `E_AXI_SLVERR(0x08)`，`STATUS.AXI_ERR=1`；
- 读返回按 `RID` 匹配，支持权重、scale、描述符三类请求共用一个 master（按 `axlen` 区分）。

**改动点**：`tpu_top` 的 `mem_raddr` 组合逻辑改为请求队列；`tpu_copy`/`tpu_mxu`
的 `mem_*` 端口改为 valid/ready 握手（与 D12 一起做最省事）。

**验收**：接 AXI 存储器模型（带随机延迟与错误注入），41 个用例全绿；
注入 `SLVERR` 时错误码为 0x08 且无部分写。

### D10 描述符环 + 片内队列（P1，M）

**现状**：`DQ_HEAD`/`DQ_TAIL` 两寄存器 + `next_desc` 单链。

**方案**
- 片内 32 × 64 B 描述符 RAM（2 KiB，8 BRAM 或寄存器堆）；
- `DQ_BASE + (idx mod 32)*64`，`idx` 为 5 bit；`DQ_HEAD`/`DQ_TAIL` 保留 CSR 语义
  （软件写 head 入队、硬件写 tail 表示完成）；
- 预取：当队列未满且 `head != tail` 时，`FETCH` 状态连续取指，最多 32 条；
- `next_desc` 仍优先（非 0 时跳转），否则按 `base` 顺序推进（与现状兼容）。

**验收**：新增"32 条描述符连续下发"用例，检查 `DQ_TAIL` 单调、吞吐不被取指卡住；
错误描述符只停在自身，不吞后续队列。

### D11 `CTRL.DQ_AUTO`（P2，S）

`CTRL[4]=1` 时忽略 `next_desc`，按 `DQ_BASE` 环形推进；`=0` 时保持现有链式行为。
`CAPS` 不变（属 CTRL 位）。验收用例：同时写 `next_desc` 与 `DQ_AUTO`，确认后者优先。

### D7 COPY 四方向（P1，M）

**方案**：把 `tpu_copy` 的 `mode` 从 1 bit 扩为 2 bit（`sbuf[1:0]`）：
`0` DRAM→DRAM、`1` TMEM→DRAM、`2` DRAM→TMEM、`3` TMEM→TMEM。
新增 DRAM→TMEM 的 16 字写口（复用 `tm_raddr1` 之外的写端口），TMEM→TMEM 走
`rd → 缓冲 → wr` 两拍。`dma_bytes` 统按实际搬运字节计。

**验收**：新增 3 个方向用例（含非 64 整行、末 beat 掩码），与 `ref_tpu` 逐字节比对。

### D2 `RMAX`（P2，M）

**语义确认**：`RMAX` 时把每行的最大值写到 `C_addr + 4`（字地址），仅 `M ≤ MCOLS`。
**方案**：epilogue 增加行最大值寄存器（8 个 fp32 比较器，遇 `+0` 与负数照常比较），
在 `epi_c == 7` 时把结果写到 `epi_addr` 的 `+4` 偏移；`flags` 掩码加入 `F_RMAX`，
`CAPS.bit3=1`。**约束**：与 `ACC` 同置时先加后取 max。

**验收**：新增 `rmax_*` 用例，模型实现 `max` 归约；`ldc` 需 ≥ `4*(n+1)` 的检查写入校验。

### D3 `ASCALE`（P2，M，需先澄清 C1）

**规格缺口**：02/03 只写了 `y = C_old × factor[j] + y`，未定义 `factor[j]` 来源。
**建议方案（评审后定稿）**：`ASCALE=1` 时把 `w14`（现 `seq`）解释为 `factor_addr`，
指向 DRAM 中按行排列的 fp32 数组（行步长 `ldc`？建议独立为 `factor` 紧凑数组，
元素 `M` 个，4 B 对齐）。`seq` 移到 `w9[31:16]` 保留位或调试口。

RTL 改动：epilogue 前对每行读 `factor[j]`，`y = f_add(f_mul(factor[j], C_old), y)`；
`flags` 掩码加 `F_ASCALE`；`CAPS.bit4=1`；`ACC` 必须同置，否则 `DESC_FLAGS`。

**验收**：新增 `ascale_*` 用例（含 `ACC` 同置、`factor=0/1/负数`），模型同步实现。

### D4 `TRANSPOSE_B`（P2，M）

**方案**：激活读地址从 `b + (j*ACT_BLOCKS + kb)*64` 改为按列主序计算
（`b + (col*ACT_BLOCKS + kb)`），`ACT` 布局不变，仅寻址变化；`flags` 掩码加 `F_TB`。
`CAPS` 不新增位（03 文 §4 未给 `TRANSPOSE_B` 分配 CAPS 位，保持 `0x27`）。
**验收**：新增 `tb_*` 用例（M×K 激活转置后与行主序结果一致）。

## 4. V2：量化与性能重构

### D6 QUANT 完整量化（P2，L）

**目标**：RTL 内完成 `amax → Sw=amax/127 → q=roundTiesToEven(x/Sw) → clamp[-127,127]
→ 每 16 元素 da → 写 ACT+scale 记录`；三值走阈值 `|x| < Δ` 判 0（Δ 由 `Sa` 与阈值寄存器给）。

**方案**
- 新增 `f_div`（或 `f_rcp` + 一次 Newton 迭代，要求与软件逐位一致，建议直接做 IEEE 除法）；
- 新增 `f2i_rne`（fp32 → int8，RNE + 饱和，复用 `f_i2f48` 的移位/粘滞逻辑）；
- 三值：`f_abs` 比较 + 码选择，`Sa` 取 `δ/2`；
- 描述符 `flags` 增加"直通/重算"位（`sbuf` 已有，复用 `sbuf[1]`）。

**验收**：与 openTPU `quant.py`（或本仓 `tests/ref_tpu.py` 扩展）对 10k 组随机张量逐位对拍；
新增 `quant_full_*` 用例；性能：每行 64 元素不超过 `64 + 16` 拍。

**风险**：除法/舍入的位精确性易错，先用 `tb_fp32` 的同款 C++ 参考单独验证 `f_div`/`f2i_rne`。

### D1 WPB=2（P1，L）

**目标**：每周期两个 64 B 权重块，8 列 1024 MAC/cycle，权重侧 128 B/cycle 吃满。

**方案**
- `tpu_mxu` 增加 `w_raddr0/1` 与 `w_rdata0/1`，`MX_CALC` 每拍处理两个 block（`kb_i += 2`）；
- 两块各自 `grp_sum` 后按各自 `sh` 移位相加，累加树从 4 组变 8 组（组合深度 +1 级）；
- 末块奇数时第二块用 `blk_cnt=0` 屏蔽；
- 需 D9 的 AXI master 提供双 beat/cycle 读（或权重预取到 TMEM/权重 SRAM）；
- `VERSION.WPB=2`，02 文 §4.1 的带宽模型改为实测口径。

**验收**：新增 `wpb2_*` 用例（三精度、奇数 `kb`、末块不足）；MAC/cycle ≥ 95% 理论值；
`scripts/synth.sh` 面积不超过预算 1.6×；`STALL_MEM` 在真实 AXI 延迟下仍低。
