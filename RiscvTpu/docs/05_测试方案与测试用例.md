## 3. 黄金模型与三方对拍

### 3.1 模型分层

```
tests/ref_vdot.py     ← 已有：三条指令的寄存器级参考（L0/L1 的真理）
        │ 被调用
        ▼
tests/ref_tpu.py      ← 新增：tile 级参考（QUANT/GEMM/epilogue），内部逐 group 调用 ref_vdot
        │
        ├──> RTL（Verilator）
        └──> openTPU 语义对照（docs/vdot-integration/02 的整数映射）
```

**关键设计**：`ref_tpu.py` 的 `c` 计算**必须**调用 `ref_vdot` 算出 8/16 路分组和再拼接，而不是独立重写一遍乘法——这样 G3（"任一 tile 结果都能用 vdot 复算"）在代码层面被强制成立。

### 3.2 difftest 规则

- 每次比对以 **16 字节为单位**，逐位相同才算通过；不允许浮点容差。
- 浮点 epilogue 也要求逐位相同：参考模型用 Python `struct` 模拟 IEEE-754 binary32 的舍入与 FTZ，不用 `float` 直接算（避免双精度污染）。
- 失配时打印：描述符 16 字 dump、首个别字地址、双方十六进制、`DBG_ACC0/1`。

设备级（T2/T4，提交点降级为"描述符退休"）：

- DUT=`tpu_top`（Verilator），REF=NEMU 内独立的 C 设备模型（`sim/difftest/tpu_ref_model.c`）。
- 必须相等：CSR 白名单、TMEM 16K 字、DRAM 1 MiB、退休地址序列；忽略：`CYCLES`/`STALL_MEM`；
  `STATUS` 用 mask `0x8F`（不比较 irq/timeout）。
- `STALL_MEM` 在 `RD_LATENCY=0` 时必须为 0；`RD_LATENCY>0` 时只做趋势观察，不参与相等比对。

> 工具选型、层间映射（L0~L4 ↔ T0~T4）与设备级 difftest 的接口设计见
> [08 验证工具链与 difftest 方案](08_验证工具链与difftest方案.md)。

## 5. 测试用例

> 记法：`M/N/K` 为描述符形状，`D=64`，`MCOLS=8`。所有"期望"均指与 `ref_tpu.py` 逐位一致，另注特殊检查。

### 5.1 MXU 数值（P0）

| ID | 目的 | 激励 | 期望 / 通过准则 |
|---|---|---|---|
| MXU-001 | int8 全正走通 | `M=8,N=1,K=64`，数据全 `+127` | 每组 `c = 16×127×127 = 258,064`，`acc = 4·c<<16`，与模型一致 |
| MXU-002 | int8 全负极值 | 数据全 `-128` | 每组 `c = 16×16384 = 2^18`，验证 48-bit 余量 |
| MXU-003 | int8 交替符号 | `+127,-128` 交替 | 无中间溢出，结果符号正确 |
| MXU-004 | int4 极值 | `K=64`，数据全 `-8` | 每组 `c = 16×64 = 1,024`，`acc = 4·c<<11` |
| MXU-005 | int4 混合 nibble | 同一字节内低 `-8` 高 `+7` | 低 nibble 在前的顺序正确 |
| MXU-006 | 三值全 `+1` | 权重码全 `01`，激活 `+127` | 每组 `c = 16×127`，零乘法器路径结果正确 |
| MXU-007 | 三值全 `-1`（边界） | 权重码全 `10`，激活 `-128` | 每组 `c = 16×128 = 2^11`，`+128` 需 9 bit |
| MXU-008 | 三值零码 | 码 `00` 与 `11` 混用，全 0 | 输出全 0，`acc=0`，epilogue 输出 `0.0` |
| MXU-009 | 单组 `sh<0` 丢弃 | 构造 `dw+da > W` 的组 | 该组不计入；其余组正常 |
| MXU-010 | `K=1` 退化 | `K=1`，`ZERO_PAD=1` | 补 0 到一块，结果等于单元素积 |
| MXU-011 | `K` 非整块 | `K=65` | 末块补 0，结果与软件模型一致 |
| MXU-012 | `M>MCOLS` 重放 | `M=16`（ACT_ROWS=64） | 分 2 轮、每轮 8 行消费同一份权重块，结果与模型一致 |
| MXU-013 | 子块 `da` 独立 | 同一 block 内 4 个 group 给不同 `da` | 每 16 个元素按各自 `sh` 缩放，结果与模型一致 |
| MXU-014 | 输出落 TMEM | 单条 `GEMM` 后读 TMEM | `C_addr+j*ldc+n` 处的 fp32 与模型逐位一致，DRAM 未被写 |

### 5.2 QUANT 与打包（P0）

| ID | 目的 | 激励 | 期望 / 通过准则 |
|---|---|---|---|
| QNT-001 | int8 量化基本 | `amax=127` 的行 | `Sw=1.0`，输出与原值相同 |
| QNT-002 | `amax=0` | 全零行 | `Sw=0`，输出全 0，不产生 NaN |
| QNT-003 | 舍入 | 恰好 `.5` 的样本 | roundTiesToEven 与参考一致 |
| QNT-004 | int4 打包顺序 | 已知序列 `-8..7` | `nibble n = bits[4n+3:4n]` |
| QNT-005 | 三值打包顺序 | 已知码序列 | 码 `i` 在 `bits[2i+1:2i]`，字节内低码在前 |
| QNT-006 | 三值阈值 | `|x|<0.5·Sw` | 输出码 `00` |
| QNT-007 | 与 `vdot` 输入对齐 | QUANT 输出直接喂 `vdot4x2`/`vtdot` | 指令结果 = 参考分组和 |
| QNT-008 | scale 行布局（openTPU 兼容） | int8 与 int4 各一行，`k0=2` | `Sw` 在字节 0..3；int8 的 `dw` 在 `4+k0+k`；int4 的 `dw`/`m` 在 `8+4*(k0+k)`，逐位与 openTPU 格式一致 |
| QNT-009 | 外部量化产物直通 | 载入 openTPU `quant.py` 产物 | 不重算 `amax`，打包结果与源逐位一致 |

### 5.3 描述符与 CSR（P0/P1）

| ID | 目的 | 激励 | 期望 |
|---|---|---|---|
| DSR-001 | 单描述符 GEMM | 1 条 `GEMM` + 链尾 | `HALTED=1`，`DQ_TAIL` 前进，结果正确 |
| DSR-002 | 描述符链 | 5 条串链，含 `COPY`/`QUANT`/`GEMM` | 严格顺序，中间结果可见 |
| DSR-003 | `next_desc=0` | 链尾 | 触发 `HALTED`，不再取指 |
| DSR-004 | `END` 提前结束 | 链中插入 `END` | 后续描述符不执行 |
| DSR-005 | `NOP` 推进 | 插入 3 条 `NOP` | `ICOUNT` 不含 NOP，`seq` 推进 |
| DSR-006 | `ACC` 累加 | 两次 GEMM 同 `C_addr` | 第二次结果 = 两次之和 |
| DSR-007 | `RELU` | 负值输出 | 输出被钳到 0 |
| DSR-008 | `RMAX` | 行内最大 | 与逐行最大值逐位一致 |
| DSR-009 | `ASCALE` | `ACC` + 行因子 | 与 `old×f + new` 逐位一致 |
| DSR-010 | `SOFT_RESET` 中途 | `RUN` 中写 bit1 | 状态回 `IDLE`，队列清空，TMEM 保留 |
| DSR-011 | 计数器清零 | `CTRL.CLR_COUNTERS` | 所有计数器归零 |
| DSR-012 | `VERSION` 自适配 | 读 CSR | `{D,MCOLS,WPB}` 与位流一致 |

| ID | 目的 | 激励 | 期望 |
|---|---|---|---|
| SYS-001 | 门铃→完成 | 写 `CTRL.RUN` | `BUSY` ≤ 8 拍置位，完成后 `HALTED` |

### 5.8 性能与外部对照（P1）

| ID | 目的 | 激励 | 期望 |
|---|---|---|---|
| PRF-001 | MAC/cycle | 满速 GEMM | ≥ 90% × `MCOLS×D`（即 ≥ 460/cycle） |
| PRF-002 | 访存受限比例 | 单通道带宽限制 | `STALL_MEM/CYCLES` 与带宽模型误差 ≤ 10% |
| PRF-003 | 三精度带宽 | 同形状换 `prec` | 时间比 ≈ 1 : 0.5 : 0.25（带宽受限场景） |
| XCH-001 | 与 openTPU 整数对照 int8 | `MM WF=0, m=1, dw=da=0, W=16` | `acc>>16` == 我们的 tile 整数 |
| XCH-002 | 对照 int4 | `WF=1`，激活为符号扩展 nibble | `acc>>11` == 我们的 `r0/r1` |
| XCH-003 | 对照三值 | `WF=1`，权重 ∈ {−1,0,+1} | `acc>>11` == `vtdot` 双结果 |

> XCH 组不跑 openTPU 的 RTL，只跑其文档伪码（`docs/isa.md:204-219`）的独立实现，作为第三方语义对照。由于 V1 的 scale 行格式与之兼容（03 文 §6.5），XCH 组可以直接吃同一份量化产物：既比对"整数域"，也比对"scale 记录的解释方式"。

## 6. 回归门禁

| 级别 | 内容 | 通过条件 | 触发 |
|---|---|---|---|
| L0 | Lint + 5 条 smoke | 0 error | 每次提交 |

## 9. 缺陷分级与出口

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 数值错、死锁、部分写、错误码错 | 阻断，必须修复 |
| P1 | 性能不达标、计数器偏差、调试信息缺失 | 里程碑前修复或书面豁免 |
| P2 | 文档不一致、可读性 | 结题前修复 |

**结题出口**：P0 = 0，P1 全部修复或有书面豁免，L0~L4 全绿，覆盖率 Q4 达标。
