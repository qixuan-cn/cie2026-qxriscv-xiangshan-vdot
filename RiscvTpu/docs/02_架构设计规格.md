> 版本：V1 · 状态：**已实现（2026-11-15 与 RTL 对齐）**

## 1. 设计原则

| # | 原则 | 具体体现 |
|---|---|---|
| P1 | **不发明指令集** | 控制面是 RV64 + RVV 代码；硬件只多 CSR 与描述符，opcode 空间只保留已有三条 `vdot` |
| P2 | **整数域必须可逐位复算** | 任一 tile 结果都能用一组 `vdot`/`vdot4x2`/`vtdot` 按 `2^sh` 移位累加得到（G3） |
| P3 | **每输出只做一次浮点** | 内层全整数精确，epilogue 只做 3 次舍入乘（借 openTPU 契约） |
| P4 | **无状态、可重放** | MXU/VPU 的每个宏操作幂等；超时/出错可整条重发，不需回滚 |
| P5 | **解耦如香山** | 前端（描述符）／发射／执行／访存四段解耦，接口单向、可单独测 |
| P6 | **观测性内建** | 周期、MAC、各精度退休、访存停顿全部 CSR 可读 |

## 2. 三层计算塔

```
                    ┌──────────────────────────────────────────────┐
   L0 标量控制      │  香山 Kunminghu V2 乱序核（RV64GC + RVV）      │
   (控制平面)       │  softmax / 采样 / 地址计算 / 异常 / 驱动         │
                    └───────────────┬──────────────────────────────┘
                                    │ ① vsetvli + vdot 系列（VFEX0）
                    ┌───────────────▼──────────────────────────────┐
   L1 向量          │  RVV 1.0（VLEN=128）+ vdot / vdot4x2 / vtdot   │
   (寄存器平面)     │  归一化 / 激活 / GEMV / 量化 / epilogue        │
                    └───────────────┬──────────────────────────────┘
                                    │ ② 64 B 描述符 + doorbell（CSR）
                    ┌───────────────▼──────────────────────────────┐
   L2 矩阵          │  RiscvTpu tile 引擎                            │
   (tile 平面)      │  描述符队列 → 发射 → { MXU | DMA | QUANT }     │
                    │        TMEM 64 KiB ↔ ACT RAM 128 KiB           │
                    └───────────────┬──────────────────────────────┘
                                    │ ③ AXI4 1024-bit master
                    ┌───────────────▼──────────────────────────────┐
                    │  DDR3 控制器（单/双通道）→ HBM/DDR 外存         │
                    └──────────────────────────────────────────────┘
```

**分工判据**（避免两层重复投入）：

- K < 64 或 M = 1 且权重不驻留 → 走 L1（`vdot` 直接算，无启动开销）；
- 有 tile 复用（K ≥ 256 或 M·N ≥ 64） → 走 L2（省权重搬运，出 MAC 效率）；
- epilogue、softmax、RoPE 一律 L1（`vdot` 服务的正是这类"每行一次"的运算）。

## 3. 顶层模块划分

| 模块 | 职责 | 关键接口 | 预算 | V1 实现 |
|---|---|---|---|---|
| `tpu_top` | 互联、时钟复位、CSR 汇总 | AXI4-Lite slave、AXI4 master、IRQ | 胶合 3k LUT | ✅ 已实现（含描述符前端、校验、超时；CSR/DRAM 为寄存器侧直连，**无 AXI 壳**） |
| `tpu_front` | 描述符预取、队列、合法性检查 | TMEM↔队列、CSR `DQ_*` | 5k LUT | ⚠️ 并入 `tpu_top`：单链顺序取指，无 32 深环形容器 |
| `tpu_disp` | 每周期发射 1 个宏操作，顺序、无乱序 | 到各单元的 `cmd_t` + 握手 | 含在 front | ✅ 并入 `tpu_top` 的 `S_DISP` |
| `tpu_mxu` | 8 列 × 64 深精确整数点积阵列 + epilogue | ACT RAM 读、TMEM 写、权重流 | 30k LUT / 160 DSP | ✅ 已实现；`WPB=1`、无 `RMAX/ASCALE/TRANSPOSE_B` |
| `tpu_tmem` | 64 KiB 双口向量存储 | 各单元读写端口 | 2k LUT / 16 BRAM | ✅ 双读口 + 单写口（含仿真后门） |
| `tpu_act` | 128 KiB 激活 RAM（64 行 × 32 块 × 64 B） | 量化写、MXU 读 | 1.5k LUT / 32 BRAM | ✅ 8 读 + 1 写（含仿真后门） |
| `tpu_quant` | int8/int4/三值打包与块缩放生成 | TMEM→ACT、DRAM→ACT | 2k LUT | ⚠️ 只实现"给定尺度"的 TMEM→ACT 打包；amax/Sw 由 L1 RVV 计算 |
| `tpu_dma` | 2D strided 搬移，1024-bit | AXI4 master、TMEM | 8k LUT | ⚠️ 实现为 `tpu_copy`：64 B/拍，仅 DRAM→DRAM 与 TMEM→DRAM |
| `tpu_csr` | 寄存器、计数器、中断、门铃 | AXI4-Lite | 1k LUT | ✅ 已实现（`STALL_MEM` 恒 0、`DQ_BASE` 仅存储） |

**单向数据流约束**：`front → disp → {dma, quant, mxu} → tmem`，任何回边只能通过"完成信号 + 状态寄存器"，不允许单元之间直接组合互联。这样每个单元可以单独 out-of-context 综合（借 openTPU 的单元级面积/fmax 方法）。

## 4. 数据流与驻留策略

### 4.1 选择：权重驻留 + 激活流式 + 每周期 2 个权重块

```
        DRAM ──DMA(1024b)──> TMEM ──QUANT──> ACT RAM
                                               │ 8 块/cycle（每列 1 块）
                            ┌──────────────────┘
   DRAM ──DMA──> TMEM ──> [ 权重流 2×64 B/cycle ] ──广播──> 4 列/流
                                               │
                                          MXU 8 列 × 64 深
                                               │ 8 个 48-bit acc
                                          epilogue（4 lanes, i2f + 2 mul）
                                               │ 8 × fp32 / cycle
                                    TMEM（GEMM 直落）──COPY──> DRAM
```

- **权重广播**：本周期同一条权重块同时喂给 4 列，4 列各自乘不同的激活行。这是把"外部带宽 1 份、片上复用 4 份"的经典折中。
- **WPB=2（目标）/ WPB=1（V1 实现）**：目标形态每周期两个权重块，把 128 B/cycle 的 DRAM 带宽吃满（`17.07 GB/s @133.33 MHz`）。**【V1 实现】** 每周期只取 1 个 64 B 权重块，8 列共 512 MAC/cycle，权重侧带宽需求减半；带宽利用率上限约为目标的 1/2（偏差 D1，修复见 07 文）。
- **激活行数**：ACT RAM 有 64 行，每周期每列读 1 行 → 8 行并行 = 8 个 token（prefill）或 8 个输出行（decode 的权重维）。

### 4.2 为什么不做 tile 级 PAIR（V1）

4-bit 权重若每周期消费 2 个块（128 个元素），ACT 侧要同时读 8 列 × 2 块 = 1 KB/cycle，是当前的 2 倍，ACT RAM 银行数要翻番。V1 改为：**4-bit/三值只享受带宽减半**（同样 64 个元素，权重字节数 1/2、1/4），MAC 数不变。这样"decode 提速"的目标仍达成，代价最小。PAIR 留作 V2 参数（`PAIR: Boolean`）。

## 5. 存储层次与带宽预算

| 层次 | 容量 | 端口 | 带宽 @133.33 MHz | 说明 |
|---|---|---|---|---|
| TMEM | 64 KiB（16K × 32 bit） | 4 读 2 写（目标）/ **2 读 1 写（V1 实现）** | 2×4 B/cycle 读 | 向量寄存器文件；MXU 输出落这里 |
| ACT RAM | 128 KiB（64 行 × 32 块 × 64 B） | 8 读 1 写 | 8×64 B = 512 B/cycle | 激活驻留；只由 QUANT 写 |
| 权重缓冲 | 2 × 64 B（双缓冲，目标）/ **1 × 64 B（V1 实现）** | 1 读 | 64 B/cycle | 从 DRAM 直送；WPB=1 |
| 描述符队列 | 32 条（32 × 64 B = 2 KiB，目标）/ **2 个寄存器（V1 实现）** | 1 读 1 写 | 64 B/cycle | V1 用 `DQ_HEAD`/`DQ_TAIL` 单链，环在 DRAM，队列未在片上 |
| AXI4 master | — | 1（目标）/ **未实现（V1）** | 128 B/cycle = 17.07 GB/s | 目标 32 个 outstanding 读；V1 暴露 32 bit 字节地址 + 64 B/拍的寄存器式端口 |
| 外部 DDR3 | — | 1~2 通道 | 单通道 8.53 / 双通道 17.07 GB/s | 64-bit DDR3-1066/通道，与 openTPU 同口径 |

**总带宽守恒检查**：MXU 满速时每周期需要 128 B 权重（外部）+ 512 B 激活（片上），恰好等于 AXI 峰值；一旦落到单通道 DDR3（8.53 GB/s），MXU 利用率上限 ≈ 50%。这个数字必须写进性能报告，不能拿 17.07 GB/s 的理想值对外宣称。

## 6. 与香山的集成

### 6.1 三个方案

| 方案 | 形态 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| **A 紧耦合** | `vdot` 留在 VFEX0 | 零额外接口，已实测 | 只有寄存器级点积 | **现状，保留** |
| **B MMIO 协处理器** | TPU 作 AXI4-Lite slave + AXI4 master | 改动小、可单独验证、能跑 tile | 需软件维护一致性 | **V1 采用** |
| **C 一致性从设备** | TPU 接 CHI/ACE-Lite | 无需软件 flush | 需实现 CHI 端口，香山侧要改 | V2 评估 |

### 6.2 方案 B 的连接

```
  香山 SoC
  ┌─────────────────────────────┐
  │ Core0..N ── L2/L3 ── CHI ── DDR│
  │        │                     │
  │        └── AXI4-Lite (64 KiB 窗口 @ 0x4000_0000) ──┐
  │        └── AXI4 (1024-bit, master 口) ◄────────────┤
  │        ◄── IRQ ────────────────────────────────────┤
  └────────────────────────────────────────────────────┘
                                         RiscvTpu
```

- **地址窗口**：`0x4000_0000 + 0x0 ~ 0xFFFF` 映射 CSR（4 KiB 足够，留 64 KiB 余量）。
- **数据面**：TPU 作为 AXI master 直接访问物理地址；**不使用 openTPU 的双通道交织**，由 SoC 的地址译码决定落到哪路 DDR。
- **一致性**：V1 为软件维护。提交描述符前 `cbo.clean`（把 CPU 写的数据刷到 DRAM）；完成后 `cbo.inval`（丢弃 CPU 侧旧副本）。两条指令在香山上已有实现。
- **完成通知**：`STATUS.HALTED` 轮询（默认）或 IRQ（`CTRL.IRQ_EN`）。
- **复位**：TPU 与 SoC 同域复位；`CTRL.SOFT_RESET` 只清队列与计数器，不清 TMEM（便于调试保留现场）。
- **【V1 实现】** 上述两个 AXI 口尚未落地：`tpu_top` 直接暴露 `cfg_*`（寄存器侧）与 `mem_*`（32 bit 字节地址、64 B/拍、8 B 写掩码）端口，仿真时接零延迟存储器模型；`irq` 为单线输出。SoC 集成时在顶层加 `tpu_axil.sv` / `tpu_axi_mst.sv` 两个壳即可，内部协议不变（偏差 D8/D9，修复见 07 文）。

### 6.3 为什么不用 openTPU 的地址交织

它的 4 GiB 逻辑空间、64 B beat 交织、`CHASH` 异或通道选择，是为"加速器独占两路 DDR3"设计的（`docs/host.md:17-24`）。接到 SoC 后 CPU 与 TPU 必须看到同一套物理地址，任何私有交织都会让 `cbo`、页表、DMA 三方对不上。**V1 明确：平坦物理地址，交织由 SoC 内存控制器负责。**

## 7. 参数表

| 参数 | V1 值 | 可调范围 | 影响 |
|---|---|---|---|
| `VLEN` | 128 | 128 / 256 | 与 `vdot` 一致，改 256 需扩 `vd` 格式 |
| `D`（MXU 深度） | 64 | 32 / 64 / 128 | MAC 数、ACT 带宽、面积线性 |
| `MCOLS` | 8 | 4 / 8 / 12 | 列数、输出并行度 |
| `WPB` | 2（目标）/ **1（V1 实现）** | 1 / 2 | 权重端口数，决定能否吃满 AXI；V1 RTL 每周期只取 1 个权重块，见 06 文偏差表 |
| `ACT_ROWS` | 64 | 8~64 | token 并行度 / ACT 容量 |
| `ACT_BLOCKS` | 32 | 16~32 | K 方向驻留深度 |
| `TMEM_WORDS` | 16K | 8K~32K | 片上缓冲 |
| `DQ_DEPTH` | 32（目标）/ **未参数化（V1 实现）** | 8~64 | 描述符队列深度；V1 用 `DQ_HEAD`/`DQ_TAIL` 单链，无片内深度 |
| `PAIR` | `false` | V2 | 4-bit 满速（2× MAC）；V1 与规格一致，置 1 报 `DESC_FLAGS` |
| `COLL` | `false` | V2 | 跨核 GATHER；`CAPS.bit6=0` |

参数化的目的是**可裁剪**：如果 M2 综合超预算，第一刀降 `D` 到 32（面积减半，MAC 减半），第二刀降 `MCOLS` 到 4。

## 8. 面积与时序预算

| 项 | 预算 | 状态（2026-11-15） |
|---|---|---|
| LUT | ≤ 60,000 | 未综合（RTL 已通过 Verilator 精化与 41 个用例） |
| FF | ≤ 45,000 | 未综合 |
| DSP48E1 | 128 ~ 256（预算 160） | 未综合；8×8 有符号乘法的 DSP 映射待综合确认 |
| BRAM36 | ≤ 80 | 未综合 |
| 目标 fmax | ≥ 100 MHz（目标 133.33 MHz） | 未综合 |

**关键路径预判**（M1 就要盯）：

1. MXU 权重广播扇出 → 8 列 × 64 乘积：用寄存器复制 + 列内先打拍。
2. 64 深精确归约：DSP 级联（`PCOUT→PCIN`），不要用 fabrics 加法树。
3. epilogue：`i2f` 后两次乘法可用 DSP 打包，注意 FTZ 判定不在关键路径上。
4. AXI 1024-bit 到 TMEM 的写通路：跨时钟/跨位宽需异步 FIFO 或直接同频。

## 9. 关键设计决策记录（ADR）

| ADR | 决策 | 备选 | 理由 |
|---|---|---|---|
| ADR-01 | 控制面用描述符 + CSR，不用私有 ISA | openTPU 式 16 条宏指令 | 保持 RISC-V 身份（P1） |
| ADR-02 | 权重广播、激活 8 行并行 | 每列独立权重流 | 前者 DRAM 只读 1 份，后者片上带宽 8 倍 |
| ADR-03 | 48-bit 精确累加 + 每输出一次 fp32 | 定长整数截断 | 位精确可对拍；截断会在长 K 下溢出 |
| ADR-04 | V1 不做 tile 级 PAIR | 一开始就 2× MAC | ACT 带宽翻倍代价高于收益 |
| ADR-05 | 一致性靠软件 `cbo` | 硬件 CHI 端口 | V1 无 SoC 集成环境，硬件一致性无法验证 |
| ADR-06 | 面积以 Yosys generic 为主口径 | 只报 Vivado | 本地无 Vivado；generic 可复现（沿用本项目既有做法） |

## 11. 已决与未决问题

| # | 问题 | 结论 | 影响 |
|---|---|---|---|
| **Q1** | 量化 scale 行是否兼容 openTPU 格式 | ✅ **已定：兼容**。权重 scale 行用其 `WF=0`/`WF=1` 布局，ACT RAM 每 `(行,block)` 8 字节 `Sa + 4×da`，分组粒度 `D/4 = 16`。格式见 03 文 §6.5 | 可直接加载 openTPU `quant.py` 产物做位精确对拍（05 文 XCH 组）；`GEMM` 分组循环改为双层 |
