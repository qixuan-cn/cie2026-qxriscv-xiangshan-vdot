# 03 · 功能设计规格

> 版本：V1 · 状态：**已实现（2026-11-15 与 RTL 对齐）**
> 本文是 RTL、验证、软件三方共同的契约。凡与实现冲突，以本文为准；改本文需走评审（M0 冻结）。
> 文中"V1 实现"列/注为 RTL 实际行为；完整偏差清单见 [06 文](06_实现说明与验证报告.md) §4，修复排期见 [07 文](07_偏差修复计划.md)。

---

## 1. 契约总则

| # | 条款 | 说明 |
|---|---|---|
| C1 | **位精确** | 同一描述符、同一输入，硬件结果与黄金模型逐位相同；不含"近似"路径 |
| C2 | **幂等** | 任何宏操作可在超时/错误后整条重发；不产生部分可见状态（TMEM 写有 `dirty` 标记，只有 END 才对外可见） |
| C3 | **顺序语义** | 描述符严格按 `seq` 顺序执行；前一条完成前，后一条的任何读写都不可见 |
| C4 | **对齐** | 描述符 64 B 对齐；DRAM 访问按元素宽度对齐（int8: 1 B、int4: 1 B、三值: 1 B，但块起始必须 16 B 对齐） |
| C5 | **可见性** | 主机写数据 → `cbo.clean` → 写 `DQ_HEAD`/doorbell；TPU 完成 → `cbo.inval` 后再读结果 |
| C6 | **精度只由描述符决定** | 同一份 RTL 通过 `prec` 字段切换 int8/int4/三值，不改编译、不重配位流 |

## 2. 指令与编程模型

### 2.1 软件看到的"指令"

V1 **不新增任何 opcode**。软件侧只有四类动作：

| 动作 | 编码 | 说明 |
|---|---|---|
| `vdot.vv` / `vdot4x2.vv` / `vtdot.vv` | `opcode=0x57, funct3=000, vm=1`；`funct6=111111/111110/111101` | 已有；寄存器级点积，L1 层使用 |
| CSR 读写 | `csrrw/csrrs/csrrc` | 控制与观测 |
| MMIO 写 doorbell | `sd zero, 0(ctr_base)` | 写 `CTRL.RUN` |
| `fence` / `cbo.clean` / `cbo.inval` | 标准 RV64 | 一致性维护 |

> 这条设计让"程序"就是普通的 RISC-V 程序：编译器、调试器、perf 全部沿用。

### 2.2 `vdot` 系列的寄存器级契约（已有，固化）

| 项 | INT8 (`funct6=111111`) | INT4 (`111110`) | 三值 (`111101`) |
|---|---|---|---|
| 输入 `vs1` | 低 64 bit 内 8 × int8 | 低 64 bit 内 16 × nibble（每字节 2 个，低 nibble 在前） | 128 bit 内 16 × int8 激活 |
| 输入 `vs2` | 低 64 bit 内 8 × int8 | 低 64 bit 内 16 × nibble（同上） | 低 32 bit 内 16 × 2-bit 码 |
| 码值 | — | `sext4(bits[4n+3:4n])` | `01→+a`、`10→−a`、`00/11→0` |
| 输出 | `vd[31:0]=S`，`vd[127:32]=0` | `vd[31:0]=r0`、`vd[63:32]=r1`、其余 0 | 同 INT4 |
| 位宽 | `ACC_W=20` | `DUAL_W=12` | `DUAL_W=12` / `TERN_W=9` |
| 时序 | latency 3，1 inst/cycle | 同 | 同 |
| `vl=0` | 不写回 | 同 | 同 |
| `vm=0` / 保留 `mode=3` | 非法，`illegal=1` | 同 | 同 |

**三值码的字节内顺序**（必须与 `vtdot` 一致）：字节 `b` 内含码 `4b..4b+3`，码 `4b` 在 `bits[1:0]`。

## 3. 描述符格式（64 B）

### 3.1 字布局

| 字 | 偏移 | 字段 | 说明 |
|---|---|---|---|
| `w0` | 0x00 | `op[7:0]` \| `flags[15:8]` \| `sbuf[19:16]` \| `prec[21:20]` \| 保留 | `prec`: 0=int8 / 1=int4 / 2=三值 / 3=保留 |
| `w1` | 0x04 | `M` | 输出行数（激活行数），`1..ACT_ROWS` |
| `w2` | 0x08 | `N` | 输出列数（权重行数），≥1 |
| `w3` | 0x0C | `K` | 归约长度（元素），`1..ACT_BLOCKS×D` |
| `w4` | 0x10 | `A_addr` | 权重基址（字节，DRAM） |
| `w5` | 0x14 | `B_addr` | 激活基址（字节，DRAM）或 ACT 块号（见 op） |
| `w6` | 0x18 | `C_addr` | 输出基址：`GEMM` 为 TMEM 字地址；`COPY` 可为 DRAM 字节地址或 TMEM 字地址 |
| `w7` | 0x1C | `lda` | 权重行步长（字节） |
| `w8` | 0x20 | `ldb` | 激活行步长（字节） |
| `w9` | 0x24 | `ldc` | 输出行步长（字节） |
| `w10` | 0x28 | `scale_addr` | 权重 scale 行基址（**openTPU 兼容格式**，见 §6.5） |
| `w11` | 0x2C | `next_desc` | 下一条描述符地址；0 = 链结束（触发 HALTED） |
| `w12` | 0x30 | `k0` | 起始块号（分块执行用），低 16 bit 有效，高 16 bit 必须 0 |
| `w13` | 0x34 | `timeout` | 周期上限，0 = 默认 1,000,000 |
| `w14` | 0x38 | `seq` | 序号（完成匹配与调试）；**V1 实现解析但未参与调度**（保留给 V2 乱序/多队列） |
| `w15` | 0x3C | `srs[15:0]` + 保留 | `srs` = scale 行步长（字节，0 = 紧凑排列）；高 16 bit 必须写 0 |

> **V1 实现**：`w0[31:22]`、`w12[31:16]`、`w15[31:16]` 任一非 0 报 `DESC_FLAGS`；
> `prec=3` 报 `DESC_FLAGS`；`op` 不在 0x01~0x06 报 `DESC_OP`。校验在取指后的 `CHECK` 状态组合完成。

### 3.2 `op` 编码

| op | 名称 | 语义 | V1 规格 | V1 实现 |
|---|---|---|---|---|
| 0x01 | `GEMM` | `C[M][N] = A[N][K] × B[M][K]^T`（权重 × 激活，行主序） | ✅ | ✅ 三精度；`flags` 仅 `ACC/RELU/ZERO_PAD` |
| 0x02 | `COPY` | DRAM ↔ TMEM 的 2D 搬移（`A_addr` 源、`C_addr` 目标） | ✅ | ⚠️ 仅 DRAM→DRAM（`sbuf[0]=0`）与 TMEM→DRAM（`sbuf[0]=1`）；64 B/拍 |
| 0x03 | `QUANT` | TMEM/DRAM → ACT RAM：打包 + 生成块缩放 | ✅ | ⚠️ 仅 TMEM→ACT 的**给定尺度打包**；amax/Sw 由 L1 RVV 算好写入 TMEM（偏差 D6） |
| 0x04 | `BAR` | 屏障（单 slice 时为 NOP，保留给 V2） | ✅ | ✅ NOP |
| 0x05 | `NOP` | 空操作（用于对齐/打点） | ✅ | ✅ 推进队列但不计 `ICOUNT` |
| 0x06 | `END` | 强制结束并置 `HALTED` | ✅ | ✅ |
| 0x10~ | 保留 | 未知 op → `DESC_OP` 错误 | — | ✅ 报 `DESC_OP` |

### 3.3 `flags`

| 位 | 名称 | 含义 | V1 规格 | V1 RTL 实现 |
|---|---|---|---|---|
| 0 | `ACC` | 累加到已有输出（`C += ...`） | ✅ | ✅ |
| 1 | `RMAX` | epilogue 附带行最大值到 `C_addr+4` | ✅（`M ≤ MCOLS`） | ❌ 未实现，置 1 报 `DESC_FLAGS` |
| 2 | `ASCALE` | `y = C_old × 因子 + y`（flash-attention 重标定） | ✅（需 `ACC`） | ❌ 未实现，置 1 报 `DESC_FLAGS` |
| 3 | `RELU` | `y = max(y, 0)` | ✅ | ✅ |
| 4 | `TRANSPOSE_B` | 激活按列主序读取 | ✅ | ❌ 未实现，置 1 报 `DESC_FLAGS` |
| 5 | `ZERO_PAD` | `K` 不足一块时补 0 | ✅ | ✅（等价：末块只累加前 `K mod 64` 个元素） |
| 6 | `PAIR` | 4-bit 满速（2× MAC） | ❌ V1 必须为 0，否则 `DESC_FLAGS` | ❌ 同规格 |
| 7 | 保留 | — | 必须 0 | ❌ 置 1 报 `DESC_FLAGS` |

> V1 RTL 接受的 flags 掩码为 `FLAGS_V1 = ACC | RELU | ZERO_PAD = 0x29`；其余位一律 `DESC_FLAGS`。RMAX / ASCALE / TRANSPOSE_B 的数值与 CSR 位在规格中保留，待 V2 实现（见 06 文偏差表）。

|---|---|---|---|---|
| 0x000 | `ID` | R | `0x52545650`（"RVTP"） | ✅ |
| 0x004 | `VERSION` | R | `{主版本[31:24], 次版本[23:20], WPB[19:16], MCOLS[15:8], D[7:0]}` | ✅ `0x01010840`（V1.0 / WPB=1 / 8 列 / D=64） |

## 5. 状态机

### 5.1 顶层

| 编码 | 状态 | 行为 | 退出条件 |
|---|---|---|---|
| 0 | `IDLE` | 空闲，`STATUS.HALTED=1` | `CTRL.RUN=1` **或写 `DQ_HEAD`**，且 `DQ_HEAD≠DQ_TAIL` |
| 1 | `FETCH` | 发描述符读地址 | 下一拍进 `FETCH2` |
| 2 | `CHECK` | 校验 `op/flags/prec/shape/对齐` | 合法 → `DISPATCH`；非法 → `ERR` |
| 3 | `DISPATCH` | 按 op 发往对应单元，最多 1 条/周期 | 单元接受 |
| 4 | `RUN` | 单元执行，计数器累加 | 完成信号或 `w13.timeout` |
| 5 | `DRAIN` | 等所有写可见（TMEM→DRAM 的 COPY 完成） | 一拍后进 `HALT` 或下一条 |
| 6 | `HALT` | 置 `HALTED`，`DQ_TAIL=当前描述符`，必要时发 IRQ | `CTRL.RUN=1` 或新 doorbell |
| 7 | `ERR` | 置 `ERROR`，停止推进，`ERROR_CODE` 粘滞 | `ERROR_CODE` 被清除 |
| 8 | `FETCH2` | **V1 实现新增**：取回 64 B 描述符并锁存，转入 `CHECK` | 固定 1 拍 |

> **V1 实现说明**：`DBG_STATE` 会短暂读到 8（`FETCH2`），软件轮询应把 8 视作 `FETCH`；
> 写 `DQ_HEAD` 本身即产生一次 doorbell（与 `CTRL.RUN` 等价），便于"先写头再跑"。
> `FETCH2` 合并进 `FETCH` 的改动列入 07 文 D14。

### 5.2 单元级握手

- `cmd_valid / cmd_ready / cmd_done`，`done` 与 `valid` 不同拍（允许 1 拍以上延迟）。
- **V1 实现**：退化为 `start`（顶层在 `S_DISPATCH` 拉高一拍）+ `done`（单元单周期脉冲）；顶层在 `S_RUN` 等 `done`。无 `ready` 反压，因为单元启动即锁存全部描述符字段，不在启动拍依赖数据返回。
- 单元内部不允许缓存跨描述符状态（P4）；`ACC` 语义由 TMEM 读回实现，不是寄存器保持。
- `cmd_done` 必须先于 `dq_tail` 更新至少 1 拍，保证 CSR 读到的 `DQ_TAIL` 一定对应已完成的结果。

## 6. 精确行为

### 6.1 `QUANT`：打包与缩放

输入：TMEM 中的 fp32 或 int8 行；输出：ACT RAM 中的一个块（64 个元素）+ 一条 scale 记录。

```
amax = max_i |x_i|                  # 行内绝对值最大
Sw   = amax / 127                   # int8；int4: amax / 7；三值: amax
q_i  = clamp(round(x_i / Sw), -128..127)   # int4: -8..7；三值: sign(x_i) → {+1,-1,0}
```

- 舍入：`roundTiesToEven`，与 IEEE 一致。
- `amax = 0` 时 `Sw = 0`，整行输出 0（不产生除零）。
- 三值量化：`|x_i| < 0.5·Sw` 取 0，其余取符号（阈值可配，默认 0.5）。
- **打包顺序**：int4 低 nibble 在前（`nibble n = bits[4n+3:4n]`）；三值码 `i` 在 `bits[2i+1:2i]`，字节内低码在前——与 `vdot`/`vdot4x2`/`vtdot` 完全一致。
- **scale 记录**：同时写 ACT RAM 的 8 字节记录 `Sa + 4×da`，格式见 §6.5（openTPU 兼容）；`QUANT` 之后 `GEMM` 不再需要从 TMEM 读尺度。
- 若输入已带 scale（外部量化产物），`sbuf` 置"直通"，本 op 只做搬移与打包，不重新求 `amax`。

> **V1 实现（偏差 D6）**：RTL 只实现上面最后一条——**直通打包**。每行从 TMEM 读 16 个字
> （64 B int8 数据）+ 2 个字（`Sa` 与 4×`da`），写 ACT 的 64 B 数据块与 8 B scale 记录；
> `amax`/`Sw`/`q_i` 由 L1 的 RVV 例程（`vdot` 量化 kernel）算好后写入 TMEM。
> 描述符字段：`A_addr` = 数据源 TMEM 字地址，`B_addr` = scale 源 TMEM 字地址，
> `C_addr` = ACT 块号，`M` = 行数，`lda` = 数据行步长（字节）。
> 完整量化流水（含舍入与三值阈值）列入 07 文 D6。

### 6.2 `GEMM`：tile 级精确点积

分组的粒度与 openTPU 一致：**block = D 个元素（64），group = D/4 个元素（16）**，`dw` 按 block、`da` 与 `m` 按 group。

```
for n in 0..N-1:
  for j in 0..M-1:
    acc = 0                                   # 48-bit 有符号
    for k in 0..KB-1:
      for g in 0..3:                          # 每个 block 4 个 group
        c   = Σ_{i in g} a[j][k][i] * w[n][k][i]        # 精确，16 元素
        sh  = W - dw(n,k) - da(j,k,g)
        acc = acc + (sh >= 0 ? (m(n,k,g) << sh) : 0) * c
    y = (i2f(acc) * Sw[n]) * (Sa[j] * f32(2^-W))       # 3 次舍入乘，FTZ
    if RELU:   y = (y < 0) ? 0 : y
    if ASCALE: y = C_old * factor[j] + y
    if ACC:    y = C_old + y
    T[C_addr + j*ldc + n] = y                 # 输出落 TMEM（V1 决定）
```

- `W = 16`（int8）/ `11`（int4、三值）。
- 权重元素：int8 为 `sext8`，int4 为 `sext4`，三值为 `{+1,0,-1}`。
- 激活元素：int8（`sext8`）；**int4/三值模式下激活仍以 int8 存放**（−8..7 精确可表示），这样 `c` 的上界推导与 01 文 §2.3 一致。
- `KB = K / D`（向上取整；`ZERO_PAD=1` 时末块补 0）。
- **输出落 TMEM**（`C_addr` 为 TMEM 字地址，`ldc` 以字节计但必须是 4 的倍数）；需要回 DRAM 时由后续 `COPY` 描述符搬运。理由：epilogue 与 TMEM 同域，省一次 AXI 往返；且 `ACC`/`ASCALE` 的读回天然走 TMEM。
- 溢出：48-bit 保护触发即 `ACC_OVERFLOW` 错误（按 01 文 §2.3 的上界不应发生，属断言）。

> **V1 实现**：`ACC`/`RELU` 已实现；`RMAX`/`ASCALE`/`TRANSPOSE_B` 置 1 报 `DESC_FLAGS`
> （偏差 D2~D4）。`ZERO_PAD` 无需软件补零：末块只累加前 `K mod 64` 个元素，等价补 0。
> `K < 64` 时同样走掩码路径，`kb=1`。epilogue 的两次舍入乘在 RTL 中为
> `f_mul(f_mul(i2f(acc), Sw), f_scale_pow2(Sa, -W))`，FTZ/DAZ 与零规范化为 `+0`。

### 6.3 `COPY`

2D strided：以 `(行数 = M, 行内字节 = lda, 行步长 = ldb)` 描述，源 `A_addr` → 目标 `C_addr`。`sbuf` 选择走 TMEM 中转还是直通。用于权重预取与结果回写（TMEM → DRAM）。

> **V1 实现（偏差 D7）**：只实现两个方向——`sbuf[0]=0` 为 DRAM→DRAM（`A_addr`/`C_addr` 字节地址，
> `ldb`/`ldc` 字节行步长）；`sbuf[0]=1` 为 TMEM→DRAM（`A_addr` 为 TMEM 字地址、`ldb` 为字行步长，
> `C_addr` 为 DRAM 字节地址、`ldc` 为字节行步长）。每行按 64 B beat 搬运，末 beat 用字节掩码。
> DRAM→TMEM 与 TMEM→TMEM 列入 07 文 D7。

### 6.4 `BAR` / `NOP` / `END`

`BAR`：单 slice 为 NOP；V2 多 slice 时等待所有 slice 到达。`NOP`：仅推进 `seq`。`END`：置 `HALTED`，不再取描述符。

### 6.5 scale 行格式（**与 openTPU 兼容**）

V1 明确采用 openTPU 的 scale 记录格式（`../../openTPU-main/docs/isa.md:228-251`），目的是**直接加载其 `opentpu/quant.py` 的量化产物做位精确对拍**，而不是各写一套。

#### 权重 scale 行（DRAM，`scale_addr + n*srs`，`n` = 输出列号）

`prec=0`（int8，对应 openTPU `WF=0`）：

| 字节偏移 | 内容 |
|---|---|
| 0..3 | `Sw[n]`（fp32，行尺度） |
| `4 + k0 + k` | block `k` 的 `dw`（uint8）；`m = 1` |

`prec=1/2`（int4 / 三值，对应 openTPU `WF=1`）：

| 字节偏移 | 内容 |
|---|---|
| 0..3 | `Sw[n]`（fp32） |
| 4..7 | 保留（0） |
| `8 + 4*(k0+k)` | bits[7:0] = block `k` 的 `dw`；group `b`（0..3）的 `m` = bits`[8+6b +: 6]`（0..63），三值取 `m ∈ {0,1}` |

- `srs = 0` 表示紧凑排列：int8 为 `4 + 总块数`，int4/三值为 `8 + 4×总块数`。
- 对齐：`scale_addr` 与 `srs` 在 int8 下须 4 B 对齐，int4/三值下须 8 B 对齐。
- 索引方式与 openTPU 相同：描述符的 block `k` 对应 scale 行的 block `k0 + k`。

#### 激活 scale 记录（ACT RAM，每 `(行 j, block k)` 8 字节）

| 字节偏移 | 内容 |
|---|---|
| 0..3 | `Sa[j][k]`（fp32，行块尺度） |
| 4 | group 0 的 `da`（uint8） |
| 5 | group 1 的 `da` |
| 6 | group 2 的 `da` |
| 7 | group 3 的 `da` |

group `b` 的实际尺度为 `Sa · 2^-da[b]`；`D=64` 时每 group 16 个元素，与 openTPU 的"`D/4` 元素一个子块、四个 8-bit 偏移"完全一致。

**兼容性结论**：给定同一组权重与激活，openTPU 的 `quantize_mxu` 产物可直接写入本项目的 `scale_addr` 与 ACT RAM；反之我们的 `QUANT` 输出也能喂给 openTPU 的 `MM`。这是 05 文 XCH 组用例的前提。

## 7. 时序契约

| 项 | 值 | 说明 |
|---|---|---|
| `vdot` latency | 3 cycle | 实测 |
| `vdot` 吞吐 | 1 inst/cycle | 实测 |
| `vdot` 与 `vdot4x2`/`vtdot` 互切 | 无气泡 | 同一数据通路，仅 EX1 选择不同 |
| doorbell → `STATUS.BUSY=1` | ≤ 8 cycle | 目标 |
| `GEMM` 首输出 | ≤ 16 + `KB` cycle | 目标（含权重预取） |
| 完成 → IRQ | ≤ 16 cycle | 目标 |
| `DRAIN` | ≤ 64 cycle | 单次最大 outstanding 写 |

以上"目标"值在 M2 用周期精确模型校准；**实测值一旦偏离，以实测为准并更新本文**。

> **V1 实测状态**：`vdot` 的三项（latency 3、1 inst/cycle、互切无气泡）已在香山侧实测，
> 其余五项为 RTL 目标值，尚未做周期精确统计。`GEMM` 的单块节拍为：
> `MX_SW`(1) + `MX_WR`(1) + `MX_CALC`(1/block) + `MX_EPI0/1`(2/列)，
> 即每个 `(列, 行组, block)` 约 3 拍 + epilogue 2×8 拍；WPB=1 时 8 列共 512 MAC/cycle。

## 8. 错误模型

| 码 | 名称 | 触发 | 是否粘滞 | 行为 |
|---|---|---|---|---|
| 0x00 | `NONE` | — | — | — |
| 0x01 | `DESC_ALIGN` | 描述符地址未 64 B 对齐 | 是 | 停 |
| 0x02 | `DESC_RANGE` | `DQ_BASE/HEAD` 越界或环不一致 | 是 | 停 |
| 0x03 | `DESC_OP` | 未知 `op` | 是 | 停 |
| 0x04 | `DESC_FLAGS` | 非法 flags 组合（含 `PAIR=1`、`w15[31:16]≠0`、`w0[31:22]≠0`） | 是 | 停 |
| 0x05 | `SHAPE` | `M>ACT_ROWS` / `K>ACT_BLOCKS×D` / `N=0` | 是 | 停 |
| 0x06 | `ADDR_ALIGN` | 块起始未 16 B 对齐 | 是 | 停 |
| 0x07 | `AXI_DECERR` | 访问未映射地址 | 是 | 停 |
| 0x08 | `AXI_SLVERR` | 从设备错误响应 | 是 | 停 |
| 0x09 | `TIMEOUT` | 超过 `w13.timeout` | 否 | 停，可重发 |
| 0x0A | `ACC_OVERFLOW` | 48-bit 溢出（断言） | 是 | 停 |
| 0x0B | `SBUF` | `sbuf` 越界 | 是 | 停 |

- **粘滞**：只有写 `ERROR_CODE=1` 或 `CTRL.SOFT_RESET` 才清除。
- **不写部分结果**：任一错误发生时，当前描述符对 DRAM 的写全部丢弃（TMEM 内部可有中间值，但 `TMEM_DIRTY` 置位且不会自动回写）。
- **V1 实现**：0x01（描述符地址非 64 B 对齐）、0x03、0x04（含 `PAIR`、保留位、`prec=3`、
  `RMAX/ASCALE/TRANSPOSE_B`）、0x05、0x06、0x09（`w13.timeout`，默认 1e6，**不粘滞**）、
  0x0A、0x0B 均已实现并有用例；0x02 仅覆盖 `C_addr` 越界（无 `DQ_BASE` 环检查）；
  **0x07/0x08 在 V1 不可达**——没有 AXI 主机，DRAM 为零延迟模型，故 `STATUS.AXI_ERR` 也恒 0。
  错误码在 `ERR` 状态后一拍才落定，软件轮询应先读 `STATUS.ERROR` 再读 `ERROR_CODE`。

## 9. 性能计数器

| 计数器 | 定义 |
|---|---|
| `CYCLES` | `STATUS.BUSY=1` 的周期总数 |
| `ICOUNT` | 完成的描述符数（不含 NOP） |
| `MAC_LO/HI` | `Σ 描述符 (M × N × KB × D)`；三精度同口径，**不按位宽折算** |
| `STALL_MEM` | `RUN` 中 MXU 因权重/激活未就绪而停的周期（**V1 恒 0**，见偏差 D12） |
| `RETIRE_INT8/4/TERN` | 按 `prec` 分类的描述符数 |
| `DMA_BYTES` | 实际搬运字节 |

派生指标（软件计算，不占硬件）：

```
有效 MAC/cycle = MAC / CYCLES
MXU 利用率      = 有效 MAC/cycle / (MCOLS × D)
访存受限比例    = STALL_MEM / CYCLES
```

## 10. 复位、调试与版本

- **复位**：`rst` 异步置位、同步释放；清队列、状态机、计数器；**不清 TMEM/ACT**（保留现场）。
- **调试**：`DBG_*` 只读，不改变行为；`TRACE`（CAPS bit7）在 V1 恒 0。
- **版本**：`VERSION` 只随不兼容变更递增；新增 flags/op 属于兼容扩展，不改进次版本。
- **V1 冻结项**：描述符 16 字布局、CSR 偏移、错误码、三条 `vdot` 语义。
