# 04 · 项目开发计划

> 版本：V1 规格期 · 状态：草案（待评审）
> **本计划以"阶段 + 交付物 + 退出准则"组织，不排日历工期**；阶段之间的依赖与并行关系见 §3。

---

## 1. 计划原则

| # | 原则 | 含义 |
|---|---|---|
| D1 | **先冻结契约，再写 RTL** | 描述符、CSR、`vdot` 语义在 M0 冻结；之后只允许兼容扩展 |
| D2 | **每阶段可独立验收** | 每阶段都有"能跑的命令 + 可看的报告"，不靠"整体完成" |
| D3 | **不重复已有资产** | `vdot` FU、3,047 单元用例、55 覆盖率点、3,032 协同用例直接沿用 |
| D4 | **先小后大** | `D=32` 的 mini 配置先跑通全链路，再放大到 `D=64` |
| D5 | **每阶段留可回退点** | 每个里程碑打 tag / 归档综合报告，便于二分定位 |

## 2. 阶段划分

### M0 · 规格冻结

| 项 | 内容 |
|---|---|
| 交付物 | 本目录 5 份文档评审通过并冻结；描述符/CSR 表格导出为 `sw/tpu_regs.h`（机器可读）；`vdot` 语义冻结声明 |
| 关键工作 | 评审 5 份文档；确认 Q3/Q4 未决问题（Q1/Q2 已定：scale 行兼容 openTPU、输出落 TMEM）；确定 `D`/`MCOLS` 初值 |
| 退出准则 | ① 5 份文档无阻断性意见；② `tpu_regs.h` 能生成且与文档一致；③ 反例清单（哪些必须报错）确认 |
| 依赖 | 无 |

### M1 · 单元级 RTL 与黄金模型

| 项 | 内容 |
|---|---|
| 交付物 | `tpu_mxu`（`D=32` mini）、`tpu_tmem`、`tpu_act`、`tpu_quant` 的 RTL + 单元 tb；`tests/ref_tpu.py`（tile 级黄金模型） |
| 关键工作 | MXU 精确归约（DSP 级联）；epilogue 三次舍入 + FTZ；QUANT 打包顺序对齐 `vdot` |
| 退出准则 | ① MXU 与黄金模型 10^5 随机 + 边界用例 0 失配；② QUANT 打包结果与 `vdot4x2`/`vtdot` 输入格式逐位一致；③ Yosys generic 计数落在预算的 ±20% |
| 依赖 | M0 |
| 风险 | R1（面积）、R2（时序）——本阶段先出 generic 计数，不追 fmax |

### M2 · 子系统集成

| 项 | 内容 |
|---|---|
| 交付物 | `tpu_dma`、`tpu_front`（描述符队列）、`tpu_disp`、`tpu_csr`；子系统 tb（AXI-Lite 寄存器 + 内存模型） |
| 关键工作 | DQ 环取指、校验、单条 GEMM 端到端（DRAM→ACT→MXU→TMEM→DRAM）；错误注入 |
| 退出准则 | ① 单条 GEMM 端到端逐位正确；② 12 类错误码全部可触发且行为符合 03 文 §8；③ 计数器与黄金模型统计一致；④ 综合报告（generic）归档 |
| 依赖 | M1 |

### M3 · 系统与板级仿真

| 项 | 内容 |
|---|---|
| 交付物 | `tpu_top`（AXI4 master + Lite slave + IRQ）；`sim/tb_board`（借用 openTPU 的"AXI-Lite + 程序加载 + 内存模型 + 随机 stall"结构）；链接脚本/驱动骨架 |
| 关键工作 | 1024-bit AXI 时序；随机 stall 下的正确性；门铃→中断全链路；`D=64` 配置 |
| 退出准则 | ① 板级 tb 上运行 10 条描述符链，含随机 stall，0 失配；② `D=64` 综合报告；③ 时序预算表更新为实测（Yosys 逻辑级数 + 估算 fmax） |
| 依赖 | M2 |

### M4 · 软件栈与微基准

| 项 | 内容 |
|---|---|
| 交付物 | `sw/vdot.h`（内建/`.insn` 封装）、`sw/tilelib`（GEMM/GEMV/QUANT 三件套）、`sw/driver`（mmap + 提交环）、三个微基准 |
| 关键工作 | 三条 `vdot` 的 intrinsics；描述符生成器；GEMM 微基准（`M=N=K=64/512/4096`） |
| 退出准则 | ① 微基准数值与黄金模型一致；② 输出 MAC/cycle、MXU 利用率、访存受限比例三项；③ `vdot` 三条指令在香山仿真上可执行（或用 `.insn` 编码验证） |
| 依赖 | M3（可用 RTL 仿真代替真实板卡） |

### M5 · 评测、文档与结题

| 项 | 内容 |
|---|---|
| 交付物 | 评测报告（三精度 × 三个规模）；回归基线；项目文档终稿；与 openTPU 的对照表更新 |
| 关键工作 | 全部回归；覆盖率收口；文档一致性检查（数字、口径、边界） |
| 退出准则 | ① L0~~L3 回归全绿；② 覆盖率达标（05 文 §4）；③ 报告里每个数字都能追到日志；④ 明确列出"未做/不可做"项 |
| 依赖 | M4 |

## 3. 依赖与并行

```
M0 ──> M1 ──> M2 ──> M3 ──> M4 ──> M5
        │       │       │
        └───────┴───────┴──> 综合/面积（可与功能并行，每个里程碑各出一次报告）
                        └──> 软件栈（可在 M2 起并行写黄金模型与描述符生成器）
```

可并行的三条线：

1. **RTL 主线**：M1→M2→M3。
2. **模型线**：黄金模型与描述符生成器从 M1 起持续演进，先于 RTL。
3. **综合线**：`D=32` / `D=64` 两套配置在每个里程碑末各出一次 generic 计数与逻辑级数。

## 4. 资源与环境

| 项 | 现状 | 缺口 | 应对 |
|---|---|---|---|
| 仿真 | Verilator（已有） | 无 UVM | 用 SV tb + Verilator，沿用现有做法 |
| 综合 | Yosys 0.52（`.tools/yosys`，已装） | 无 Vivado | generic 计数为主口径；fmax 用逻辑级数 + 经验模型，标注"估算" |
| 板卡 | 无 | 无 PCIe 卡 | M3 止于板级仿真；不承诺实测 tok/s |
| 香山环境 | 已有 `vdot` 协同仿真链路 | 无完整 SoC 仿真 | L1 复用现有；L2 用独立 tb |
| 工具链 | GCC/LLVM（需确认自定义指令支持） | 汇编器可能不认 `vdot` | `.insn` 编码兜底；编码表已在 03 文 §2.1 |

## 5. 评审门

| 门 | 时机 | 通过条件 | 不通过的处理 |
|---|---|---|---|
| G0 | M0 末 | 5 份文档 + `tpu_regs.h` 一致 | 回改文档，不进入 M1 |
| G1 | M1 末 | 单元 0 失配 + 面积在预算 ±20% | 降 `D` 到 32 或 `MCOLS` 到 4 |
| G2 | M2 末 | 端到端 GEMM 正确 + 错误码全覆盖 | 修复后再进 M3 |
| G3 | M3 末 | 板级 tb 全绿 + `D=64` 综合归档 | 时序不收敛则降配或加流水 |
| G4 | M4 末 | 微基准三项指标可复现 | 不出结论，先修性能模型 |
| G5 | M5 末 | 回归全绿 + 覆盖率达标 + 文档一致 | 结题延期，列缺口 |

---

## 6. 变更管理

- **描述符/CSR/错误码**：冻结后只允许"新增字段 + 保留位"，不允许改语义；改语义需升主版本并同步黄金模型与 tb。
- **`vdot` 语义**：不属本项目变更范围（已实测固化）。
- **参数默认值**（`D`/`MCOLS`/`WPB`）：允许在 M1/M2 调整，调整需更新 02 文 §7 与面积预算。
- **文档与代码同步**：任何 RTL 改动导致 03 文表格失效，必须在同一提交内改文档。

## 8. 明确不做（写进结题报告）

1. 上板实测（无卡）。
2. 完整 SoC 异构仿真（无香山 SoC 环境）。
3. 多 slice / `GATHER`（V2）。
4. tile 级 `PAIR`（V2 参数）。
5. 训练的 ANY 形式（无反向通路）。
6. 图编译器 / 算子融合（V1 只到 tile 库）。
