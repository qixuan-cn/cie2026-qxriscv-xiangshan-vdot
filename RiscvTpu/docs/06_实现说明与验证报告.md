## 3. 数值契约的实现要点

1. **精确整数内层**：`grp_sum` 逐元素 `a*w` 得 16 bit 有符号积，组内 16 项累加到
   24 bit，4 个 group 各自左移 `2^sh` 后拼成 48 bit（`acc` 内部用 64 bit 承载），
   代码保证 `|acc| < 2^47` 时与无限精度一致；越界时 `tpu_mxu` 置 `err_ovf` →
   `ACC_OVERFLOW`。
2. **每输出一次 fp32 epilogue**：
   `y = f_mul(f_mul(f_i2f48(acc), Sw), f_scale_pow2(Sa, -W))`，
   `f_mul` 只舍入一次（guard/sticky/round-to-nearest-even），整体相当于规格要求的
   "两次舍入乘"。`f_i2f48` 的 sticky 位只统计 guard 以下（`h-24`），这是本项目修掉的
   唯一数值 bug（曾导致恒偏大 1 ulp）。
3. **FTZ / DAZ / 非有限数**：`tpu_pkg` 的 `f_mul`/`f_add` 把次正规输入与输出都当 0，
   非有限数结果归零。因此零结果恒为 `+0x00000000`，与黄金模型一致。
4. **末块掩码**：`blk_cnt = K - b*64`（仅末块），`grp_sum(..., cnt)` 只累加
   `e < cnt` 的元素。这与 `ZERO_PAD` 语义等价，因此 `K` 不是 64 的倍数时无需软件补零。
5. **`srs=0` 紧凑行宽**：int8 为 `4 + kib`，int4/三值 `8 + 4*kib`（`kib` = 该 tile 的 block 数）；
   `srs≠0` 时按字节行步长解释。`k0` 是**绝对块号**，`s_raddr` 用 `4+k0+b`（int8）或
   `8+4*(k0+b)`（int4/三值），与 openTPU 的续算语义一致。
6. **三值编码**：`01→+a`、`10→−a`、`00/11→0`；int4 为 4 bit 二补数（低 nibble 是偶元素）。

`f_mul` / `f_add` / `f_i2f48` / `f_scale_pow2` 已用 C++ IEEE 参考做 495,448 条随机与
边界对拍，**0 失败**（含 20 万随机正规数、2 万近抵消加法、FTZ 边界、48 bit 边界）。

## 4. 实现偏差表（V1 已知限制）

| # | 规格 | V1 实现 | 影响 |
|---|---|---|---|
| D1 | `WPB=2`（每周期 2 个权重块） | **WPB=1**：`MX_CALC` 每周期算 1 个 block，8 列共 512 MAC/cycle | 权重带宽利用率约为目标的 1/2；功能与数值不受影响 |
| D2 | `RMAX` flag | 未实现，置 1 报 `DESC_FLAGS` | `CAPS.bit3=0` |
| D3 | `ASCALE` flag | 未实现，置 1 报 `DESC_FLAGS` | `CAPS.bit4=0` |
| D4 | `TRANSPOSE_B` flag | 未实现，置 1 报 `DESC_FLAGS` | 激活只支持行主序 |
| D5 | `PAIR` | 与规格一致：必须 0 | — |
| D6 | `QUANT` = TMEM 激活 → int8 + amax/Sw 计算 + 写 ACT | 只做**给定尺度**的打包：每行 16 个 TMEM 字 → ACT 64 B，2 个 TMEM 字 → 8 B scale 记录；amax/Sw 由 L1 的 RVV 例程算好后写进 TMEM | 量化算法留在软件（与 vdot 量化例程一致），RTL 只做搬移 |
| D7 | `COPY` 四种方向 | 实现 DRAM→DRAM（`sbuf[0]=0`）与 TMEM→DRAM（`sbuf[0]=1`）；DRAM→TMEM、TMEM→TMEM 未实现 | 规格中 V1 只需要前两种 |
| D8 | AXI4-Lite 从口 | 直接暴露 `cfg_we/re/addr/wdata/rdata` 寄存器侧；`irq` 单线 | SoC 集成时加一层 `axil` 壳，逻辑不变 |
| D9 | AXI 主机（128 B/beat） | DRAM 侧为 32 bit 字节地址、1 拍 64 B、写带 64 bit byte-strobe；scale 读为 4 B 窗口 | V1 用零延迟模型；接真实 AXI 时在顶层加 64→512 bit 的打包器 |
| D10 | `DQ_DEPTH=32` 环形描述符队列 | 只有 `DQ_HEAD`/`DQ_TAIL` 两个寄存器，按 `next_desc` 形成**单链**顺序执行，链尾回 HALT | 无多描述符预取/乱序；`DQ_BASE` 仅存储 |
| D11 | `CTRL.DQ_AUTO` | 未实现（恒按链式取指） | 软件写 `next_desc` 即可 |
| D12 | `STALL_MEM` 计数 | 恒读 0 | 观测性缺失，不影响功能 |
| D13 | ACT / TMEM 端口 | 仿真/DFT 后门（`act_h_*` / `tm_h_*`）与单元端口复用 | 真实集成时后门接 0 |
| D14 | `S_FETCH2` | 规格状态机之外增加的取指打拍状态 | `DBG_STATE` 会短暂读到 8 |
| D15 | 综合面积/时序 | 尚未做门级综合（Yosys 0.52 的 SV 前端不支持本工程使用的 `return` 式 function 与 `always_ff` 内局部变量） | 面积/频率数字仍为 02 文的预算值 |

> 偏差 D1~D14 全部在规格的"V1 可裁剪"范围内；D15 属工具限制，不影响功能验证。
> 逐条的修复方案、改动点、验收标准与 V1.1/V1.2/V1.3/V2 排期见
> [07_偏差修复计划.md](07_偏差修复计划.md)。

## 5. 验证方法

### 5.1 两级对拍

1. **数值原语级**（`sim/tb_fp32.cpp` + `sim/fp32_dut.sv`）
   把 `tpu_pkg` 的四个 fp32 函数直接引出，用 C++ `float` 实现参考（含 FTZ/DAZ、
   零规范化、48 bit 整数舍入），逐条比较 32 bit 结果。
   覆盖：`±0`、次正规、`FLT_MAX`、`2^-126`、48 bit 边界、20 万随机正规数乘法、
   2 万近抵消加法、随机 `i2f48`（零扩展与符号扩展两种）。

2. **tile 级**（`sim/tb_tpu.cpp` + `tests/ref_tpu.py`）
   黄金模型是**独立**的 Python 实现（numpy fp32 逐步模拟，不复用 RTL 代码）；
   `run_tpu_tests.py` 生成描述符/DRAM/ACT/TMEM 激励，跑 Verilator 模型，逐位比对
   TMEM、DRAM、CSR。命令语言含 `D/T/A/X/C/HEAD/DOOR/RUN/E_T/E_D/E_ERR/E_CS/E_HALT`，
   可单独复现任一用例。

## 6. 本轮修掉的问题（供回归参考）

| 现象 | 根因 | 修法 |
|---|---|---|
| fp32 `i2f48` 恒偏大 1 ulp（273/49 万失败） | sticky 掩码把 guard 位也计入 | sticky 改 `(h-24)` 以下 |
| 多列 GEMM 只有第 0 列正确 | `acc[]` 只在描述符起点清零，列/jg 切换时残留 | `kb_i==0` 时累加器从 0 开始 |
| ACC 用例随机失败 | 测试里 `acc_init` 是每次调用都重新采样的 lambda，写进 TMEM 的值与模型期望不是同一组 | 先生成矩阵再写/算 |
| int4/三值多 block 失败 | 测试把权重块按 64 B 间隔摆放，RTL 按 `blk_bytes`（32/16 B）紧凑寻址 | 测试改用 `BLK_BYTES` 布局 |
| TMEM 结果偶发错位 | epilogue 的 `tm_we`/`tm_waddr` 与数据不同拍 | 增加 `tm_waddr_r`，与 `tm_we`/`tm_wdata` 同拍寄存 |
| 错误码读回为 0 | 测试在 `RUN` 之前就检查 CSR，且错误码比 `state=ERR` 晚一拍落定 | 期望检查延后到全部激励之后；`RUN` 结束后补 2 拍 |
| `dma_bytes` 跨描述符累加 | `tpu_copy` 起始未清零 | `C_IDLE` 接受 `start` 时清零 |
