## 1. 范围与参考

本规格书定义 `vdot.vv` 的**指令级精确语义（SSR）**、**微架构规格（MAS）** 与 **软硬件接口（ICD）**，是所有 RTL、验证、NEMU 建模与文档的唯一事实来源。

- 目标平台：香山昆明湖 V2（Chisel 实现，Verilator 仿真）
- 固定参数：VLEN = 128，SEW = 8，分组长度 K = 8
- 不在本规格范围：内存访问、FP、LMUL>1 语义、异常精确性以外的流水线优化

参考：RISC-V V 扩展 1.0（向量配置、`vl`/`vstart`/`vm` 语义）、香山昆明湖 V2 向量执行单元代码（以 xs-env 检出分支为准）。

## 2. 指令语义规格（SSR）

### 2.1 汇编格式

```
vdot.vv  vd, vs1, vs2
```

- 语义：把 `vs1` 与 `vs2` 低 64 bit 内的 8 个有符号 int8 逐元素相乘，8 个乘积求和，结果写入 `vd` 的第 0 个 32 bit 元素；`vd` 其余位全清零。
- 无标量操作数、无内存访问、无副作用（不写 `vxrm`/`vxsat`/`vcsr`）。

### 2.2 建议编码

| 字段 | 位域 | 取值 | 说明 |
|---|---|---|---|
| funct6 | [31:26] | `111111` | **已定值**：RVV 保留编码空间，与 RVV 1.0 全部已分配项无冲突（O2 关闭） |
| vm | [25] | `1` | 仅支持无掩码形态 |
| vs2 | [24:20] | 源寄存器 2 | |
| vs1 | [19:15] | 源寄存器 1 | |
| funct3 | [14:12] | `000`（OPIVV） | 复用标准向量整数运算编码空间 |
| vd | [11:7] | 目标寄存器 | |
| opcode | [6:0] | `1010111`（0x57, OP-V） | |

编码在 RTL 中作为 **单一常量组**（`VDotOpcode`）实现，若官方给出其他编码，只改常量与 Decode 表项。

### 2.3 精确伪代码（口径 A，规范性）

```python
def vdot_vv(vd, vs1, vs2):
    # 前置：SEW == 8，LMUL == 1，vm == 1，否则非法指令
    if vl == 0:
        return                     # 不写 vd，不置 dirty
    s = 0
    for i in range(8):             # 只用低 64 bit
        a = sext8(vs1_bits[8*i +: 8])
        b = sext8(vs2_bits[8*i +: 8])
        s += a * b                 # 精确整数，无饱和
    vd_bits[31:0]  = s[31:0]       # 32 bit 二补码
    vd_bits[127:32] = 0
    mark_vd_dirty()                # 整寄存器（128 bit）脏
```

### 2.4 结果位宽推导（为什么要 32 bit）

| 步骤 | 量 | 推导 | 位宽结论 |
|---|---|---|---|
| 单乘积 | `a*b`，`a,b ∈ [-128,127]` | 极值：`-128×127 = -16256`，`-128×-128 = 16384`，`127×127 = 16129` | 16 bit 有符号足够 |
| 8 项和 | `Σ a_i b_i` | 最大 `8×16384 = +131072`；最小 `8×(-16256) = -130048` | **19 bit 有符号**才能表示（18 bit 上界仅 131071） |
| 内部累加器 | `ACC_W` | 取 20 bit，留 1 bit 余量 | 20 bit |
| 输出元素 | `vd[0]` | 取 32 bit，符号扩展自 `S` | 32 bit |
| 其余通道 | `vd[127:32]` | 固定清零 | 96 bit |

> 关键结论：`+131072` 恰好越过 18 bit 有符号上界。这是本设计最容易被写错的一个点（用 16 bit 或 18 bit 累加都会在"全 -128 输入"用例上溢出），已列为必测边界用例 TC-B03。

### 2.5 语义判定表（规范性）

| 条件 | 行为 | 依据 |
|---|---|---|
| `vl == 0` | 不写 `vd`，不置 dirty，正常退休 | V 扩展：无元素写入 |
| `vl >= 1` | 写全 128 bit：`{96'b0, sext32(S)}` | 见 §2.3 |
| `vm == 0` | 触发 illegal-instruction 异常 | 未定义形态显式拒绝（ADR-04） |
| `SEW != 8` | illegal-instruction | 语义仅对 int8 定义 |
| `LMUL != 1` | illegal-instruction（v1）；v2 可选支持"按寄存器独立执行" | 避免组内布局歧义 |
| `vstart != 0` | **幂等重算**：完整重算一次并写回；`vstart` 不影响结果 | 单元无状态，重算安全（见下） |
| tail / aggr（`vta`/`vma`） | 无关：无论何种策略都写满 128 bit | 输出布局固定 |
| `vxrm` / `vxsat` | 不读取、不修改 | 整数指令 |

**vstart 幂等性论证**：`VDot` 不保存任何跨指令状态（无累加器残留、无分区进度），其结果仅由两个源寄存器内容决定。因此中断后无论从 `vstart=0` 还是任意 `vstart` 重放，只要源寄存器不变，写回值一致；重放不会产生"半个结果"。这是选择"单 uop 无状态"设计的主要收益之一（ADR-03）。

### 2.6 边界闭式结论（直接映射为测试向量）

| 用例 | 输入 | 期望 `vd[31:0]`（十进制 / 十六进制） |
|---|---|---|
| 全 +127 | 127×127×8 | 129032 / `0x0001F808` |
| 全 -128 | -128×-128×8 | **131072 / `0x00020000`**（19 bit 边界） |
| -128 × +127 | -16256×8 | -130048 / `0xFFFE0400` |
| 全 0 | 0 | 0 / `0x00000000` |
| 交替 ±1 | 1,-1,1,-1,... | 0（抵消验证） |

## 3. 微架构规格（MAS）

### 3.1 单元定位

| 项 | 规格 |
|---|---|
| 形态 | 新增一个向量功能单元（VFu），**不新增流水线**，挂接既有向量发射/写回框架 |
| 每指令 uop 数 | 1（整 128 bit 一次处理） |
| 流水 | 全流水、无状态、可背靠背发射 |
| 延迟（issue→WB 可见） | 3 周期（EX1 乘 / EX2 加法树+格式化 / WB） |
| 吞吐 | 1 条/周期（在同端口无竞争前提下） |
| 阻塞行为 | 不阻塞、不产生重放、不做跨 uop 归约 |
| 时钟域/复位 | 与向量执行单元同域；同步复位，复位后输出 valid=0 |

### 3.2 数据通路

```
        vs1 payload [63:0]                vs2 payload [63:0]
   ┌──┬──┬──┬──┬──┬──┬──┬──┐        ┌──┬──┬──┬──┬──┬──┬──┬──┐
   │7 │6 │5 │4 │3 │2 │1 │0 │        │7 │6 │5 │4 │3 │2 │1 │0 │  (int8 lanes)
   └─┬┴─┬┴─┬┴─┬┴─┬┴─┬┴─┬┴─┬┘        └─┬┴─┬┴─┬┴─┬┴─┬┴─┬┴─┬┴─┬┘
     │  │  │  │  │  │  │  │             │  │  │  │  │  │  │
     ▼  ▼  ▼  ▼  ▼  ▼  ▼  ▼             ▼  ▼  ▼  ▼  ▼  ▼  ▼  ▼
   ┌──────────────────────────────────────────────────────────┐
   │              8 × 有符号 8×8 乘法器 (→ 16 bit)             │  EX1
   └──────────────────────────┬───────────────────────────────┘
                              ▼  p0..p7 (16 bit each)
                   ┌──────────────────────┐
                   │ 3 级加法树 (→ 20 bit) │  EX2
                   │  p0+p1 p2+p3 ...     │
                   │  → 4 → 2 → 1          │
                   └──────────┬───────────┘
                              ▼  S (20 bit, 有符号)
                   ┌──────────────────────┐
                   │ sext→32bit + 96'b0   │  EX2 末
                   └──────────┬───────────┘
                              ▼  vd payload 128 bit
                        ┌──────────────┐
                        │ 向量写回端口  │  WB
                        └──────────────┘
```

### 3.3 周期级时序

| 周期 | 动作 | 关键资源 |
|---|---|---|
| 发射 | 从 uop 取 vs1/vs2 payload（寄存器堆读），检查 `vl/vtype/vm` | 读端口 2 个（128 bit） |
| EX1 | 8 路并行 8×8 有符号乘 | 8 个乘法器 |
| EX2 | 3 级加法树（4→2→1），符号扩展为 32 bit，尾零填充 | 加法器树 + 格式化 |
| WB | 驱动写回，置整寄存器 dirty | 写回仲裁 |

> 延迟值 3 需在 D7 与昆明湖 V2 既有 VFu（如 `VAlu`/`VMul`）的对齐约定核对一次；若框架要求 2 周期，则把"格式化+尾零填充"并入 WB 级。

| 参数 | 符号 | 值 | 可配置 | 说明 |
|---|---|---|---|---|
| 向量长度 | VLEN | 128 | 否 | 平台固定 |

### 3.6 实现方案对比（ADR-02 的依据）

| 维度 | 方案 A：专用小乘法阵列（选用） | 方案 B：复用既有 VMul + 跨 lane 归约 |
|---|---|---|
| 面积 | 8 个 8×8 乘法器 + 3 级树，量级 3–6 kGE（需综合实测） | 乘法阵列可复用，但需新增 128 bit 跨 lane 归约网络与大量 mux |
| 延迟 | 3 周期 | ≥4 周期，且可能需要两次占用乘法单元 |
| 集成复杂度 | 低：一个自洽新模块 | 高：需改动既有 VMul 内部或新增旁路 |
| 对既有功能风险 | 低 | 中（共享资源引入调度耦合） |
| 4 周可行性 | 高 | 低 |
| 结论 | **采用** | 仅作为面积受限场景的备选，写入报告对比章节 |

### 3.7 控制、复位与冲刷

- **flush**：与向量执行单元统一冲刷；被冲刷的 uop 不写回、不置 dirty。
- **复位**：输出 `valid=0`，内部无有效状态（时序逻辑仅流水寄存器）。
- **背靠背 RAW**：依赖同一 `vd` 的后续指令由既有记分牌/忙表保证，不在本单元内部做旁路。
- **无中断点**：单周期完成数据计算，不引入新的精确异常点。

## 4. 接口规格（ICD，草案）

以香山 `VFu` 基类为准，下列为**结构草案**（字段名需按实际基类调整，D6 回填）：

```scala
// 草案：新增向量点积功能单元
class VDot(implicit p: Parameters) extends VFu {
  val ModuleName = "VDot"

  // 输入侧（由既有向量发射框架提供）
  //   uop        : 携带 vs1/vs2 payload、vd 索引、vm、vtype
  //   vconfig    : SEW / LMUL / vl / vstart
  // 输出侧
  //   out.valid  : 写回有效
  //   out.bits   : 128 bit vd payload = {96'b0, sext32(S)}
  //   vdDirty    : 整寄存器脏标志

  val GROUP_K = 8      // 点积分组长度
  val ACC_W   = 20     // 内部累加位宽
  val OUT_W   = 32     // 输出元素位宽
  val LATENCY = 3
}
```

**接口契约**：
1. 输入 payload 已由框架完成寄存器堆读，单元不再发起读请求。
2. 单元对 `vl==0` 必须不产生写回。
3. 单元不修改 `vxrm`/`vxsat`，不产生访存请求，不参与 FP 流水。
4. `vd` 写回粒度固定为整 128 bit（不做元素级掩码写）。

## 6. 设计决策记录（ADR）

| ADR | 决策 | 理由 | 备选与否决原因 | 回退条件 |
|---|---|---|---|---|
| ADR-01 | 输出元素 32 bit | 8 项和上界 131072，8 bit 无法容纳；32 bit 与主流 int32 累加一致 | 16 bit 饱和：会丢失精确性且与"精确求和"语义冲突 | 官方明确要求窄位宽 → 改 `OUT_W` 并加饱和 |
| ADR-02 | 专用 8 乘法器阵列 | 集成简单、延迟低、不污染既有 VMul | 复用 VMul 需跨 lane 归约，4 周内风险过高 | 面积成为评审焦点 → 报告中给 B 方案对比 |
| ADR-03 | 单 uop、无状态、整寄存器写 | 规避 vstart 分区进度与归约跨 uop 状态 | 多 uop 归约可省面积但引入状态与重放复杂度 | 若 VLEN 提升到 256+ |
| ADR-04 | 仅 M1、仅 vm=1，其余 illegal | 未定义区间显式拒绝优于猜测；便于验证 | 忽略 vm 会造成静默错误 | 官方补充语义后放开 |
