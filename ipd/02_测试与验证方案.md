## 1. 验证目标与策略

### 1.1 目标

1. 证明 `vdot.vv` 在香山昆明湖 V2 上**功能正确**（含符号、边界、配置、异常四类）。
2. 证明**集成无回归**（既有向量指令行为不变）。
3. 证明**性能收益**可量化、可复现（延迟与吞吐两个口径）。
4. 产出的每一条结论都有"可点开的证据"（日志、波形、报告截图、脚本）。

### 1.2 分层策略（V 模型裁剪）

| 层级 | 名称 | 手段 | 成本 | 是否必做 |
|---|---|---|---|---|
| L0 | 单元级 | chiseltest 直连 `VDot` 模块（若模块可脱离 VFu 框架包装） | 低（秒级） | 可选，D7 尝试 |
| L1 | 指令级 | emu（Verilator）运行自检汇编，比对 `vd` 内存镜像 | 中（分钟级） | **必做** |
| L2 | 系统级差分 | NEMU 建模 + difftest 长随机程序 | 中高 | **必做**（阶段三核心） |
| L3 | 性能级 | 裸机 `rdcycle` + 波形时间戳 + 动态指令数 | 中 | **必做**（阶段三核心） |
| L4 | 回归 | 既有向量冒烟集 + 全部 vdot 用例回归 | 低 | **必做** |

**裁剪理由**：4 周工期下，L1 是性价比最高的主战场（一次构建可跑任意多用例），L0 仅在有富余时做；L2 不作为"唯一正确性来源"，而是"随机压力+一致性证明"。

## 2. 参考模型（Golden Model）

### 2.1 Python 行为模型（唯一期望值来源）

```python
# ref_vdot.py —— 与 01 §2.3 伪代码逐行对应
def sext8(x: int) -> int:
    x &= 0xFF
    return x - 0x100 if x & 0x80 else x

def ref_vdot(vs1_bytes, vs2_bytes):
    """vs1/vs2_bytes: 长度 16 的 0..255 列表（128 bit 小端）。
    返回 vd 的 128 bit 整数（小端）。"""
    s = 0
    for i in range(8):
        s += sext8(vs1_bytes[i]) * sext8(vs2_bytes[i])
    vd = (s & 0xFFFFFFFF) | (((s >> 31) & 1) * 0)  # 32 bit 二补码
    vd &= 0xFFFFFFFF
    return vd                      # vd[127:32] 恒为 0

def pack(vd32: int) -> bytes:
    return (vd32 & 0xFFFFFFFF).to_bytes(16, 'little')
```

**要求**：该模型必须与 NEMU 的 vdot 实现**双实现交叉比对**（同一批 10k 随机向量，Python 与 NEMU 结果必须一致），再作为 RTL 的判定依据。三方一致（Python/NEMU/RTL）是阶段三最强的结论。

### 2.2 参考模型覆盖的自检

| 检查 | 方法 |
|---|---|
| 位宽边界 | 直接跑 01 §2.6 的闭式结论，与手算值比对 |
| 符号处理 | `sext8` 对 0x80/-128 与 0x7F/127 的单测 |
| 无状态泄漏 | 连续计算不同输入，结果不受前次影响 |

## 3. 测试用例矩阵

优先级：P0 = 阶段二出口必须全绿；P1 = 阶段三必须；P2 = 有余力。

### 3.1 功能用例

| ID | 名称 | 输入要点 | 期望 | 优先级 | 阶段 |
|---|---|---|---|---|---|
| TC-F01 | 正数点积 | 1..8 递增正数 | Python 模型值 | P0 | 二 |
| TC-F02 | 含负数点积 | 混合正负，含 -128 | 同上 | P0 | 二 |
| TC-F03 | 混合符号+非对称 | vs1 与 vs2 符号分布不同 | 同上 | P0 | 二 |
| TC-F04 | 随机 1000 组 | 均匀 0..255（覆盖全 256 值） | 同上 | P1 | 三 |
| TC-F05 | 全零输入 | 0×0 | 0 | P1 | 二 |

### 3.2 边界用例（重点：位宽陷阱）

| ID | 名称 | 输入 | 期望 `vd[31:0]` | 优先级 |
|---|---|---|---|---|
| TC-B01 | 最大正积 | 全 127 | `0x0001F808`（129032） | P0 |
| TC-B02 | 最大负积 | vs1 全 -128，vs2 全 127 | `0xFFFE0400`（-130048） | P0 |
| TC-B03 | 19 bit 边界 | 全 -128（-128×-128=16384） | **`0x00020000`（131072）** | P0 |
| TC-B04 | 全 0 | 0 | `0x00000000` | P0 |
| TC-B05 | 完全抵消 | 1,-1 交替 × 2 组 | 0 | P1 |
| TC-B06 | 单通道有效 | 仅 lane0 非零，其余为 0 | 单乘积值 | P1 |
| TC-B07 | 最高位符号 | 0x80 与 0x7F 组合 | 见模型 | P1 |

> TC-B03 是本设计最关键的用例：任何用 16/18 bit 累加的实现都会在此溢出为 `0x00000000` 或负数。

### 3.3 配置与异常用例

| ID | 名称 | 设置 | 期望 | 优先级 |
|---|---|---|---|---|
| TC-V01 | `vl=0` | `vsetvli` vl=0 | `vd` 保持原值，不置 dirty，正常退休 | P0 |
| TC-V02 | `vl=1` | vl=1 | 与 vl=16 结果相同（语义与 vl 无关） | P0 |
| TC-V03 | `vstart=1` | 手工置 `vstart` 后执行 | 结果正确（幂等重算） | P1 |
| TC-V04 | `vl=16` | vl=16 | 正常 | P0 |
| TC-E01 | `vm=0` | 掩码形态 | illegal-instruction 异常，`vd` 不变 | P1 |
| TC-E02 | `SEW!=8` | e16/e32 | illegal | P1 |
| TC-E03 | `LMUL!=1` | m2/m4 | illegal | P1 |

### 3.4 系统与性能用例

| ID | 名称 | 方法 | 通过判据 | 优先级 |
|---|---|---|---|---|
| TC-S01 | RAW 背靠背 | 连续两条 vdot 同一 `vd` | 无冒险错误，值正确 | P1 |
| TC-S02 | 不同 `vd` 连发 | 连续 8 条不同 `vd` | 全部正确 | P1 |
| TC-R01 | 既有向量回归 | 跑既有向量冒烟/回归集 | 0 diff | P0 |
| TC-P01 | 吞吐测量 | 100 次无依赖 vdot 循环 | 平均周期数/条，与波形一致性 ≤1 周期 | P1 |
| TC-P02 | 延迟测量 | 依赖链（`vd` 串行回灌） | 单条延迟周期数 | P1 |
| TC-P03 | 基线对比 | 基线序列 vs vdot，各 ≥1000 次 | 加速比与误差范围 | P1 |
| TC-P04 | 动态指令数 | NEMU 统计 | baseline > vdot 的指令数 | P1 |

## 4. 测试程序骨架

### 4.1 自检式功能测试（L1）

```asm
# tc_b03.S —— 全 -128 输入，期望 vd[0] = 0x00020000
.section .text
.globl _start
_start:
    vsetvli t0, x0, e8, m1, ta, ma
    la      t1, src1
    vle8.v  v1, (t1)
    la      t1, src2
    vle8.v  v2, (t1)
    vmv.v.i v3, 0x55              # 预置脏值，验证"其余通道清零"
    vdot.vv v3, v1, v2
    la      t1, out
    vse8.v  v3, (t1)              # 或按 32bit 存，取决于检查方式
    # 退出并交给测试脚本比对 out 与期望 16 字节
```

### 4.2 判定方式

| 方式 | 说明 | 适用 |
|---|---|---|
| 内存镜像比对 | 测试程序把 `vd` 存到固定地址，脚本读回与 Python 期望比对 | L1 主用 |
| difftest | 与 NEMU 逐指令比对寄存器/内存 | L2 |
| 异常检查 | 检查 `mcause`/trap 是否按预期进入 | TC-E01..E03 |

### 4.3 基线序列（阶段三，先经 NEMU 校验再上 RTL）

```asm
# baseline_dot.S —— 用标准向量指令组合实现同样语义
# 前提：vs1/vs2 的数据已在 v1/v2 低 64 bit（与 vdot 用例相同起始条件）
    vsetvli t0, x0, e8, m1, ta, ma
    vsext.vf2  v4, v1             # i8 -> i16（低 8 元素）
    vsext.vf2  v6, v2
    vsetvli t0, x0, e32, m2, ta, ma
    vwmul.vv   v8, v4, v6         # i16×i16 -> i32（8 元素，m2 组）
    vmv.v.i    v0, 0
    vredsum.vs v0, v8, v0         # 归约到 v0[0]
```

> **注意**：宽化指令的目标 EMUL = 2×源 EMUL，因此 `vwmul` 需要 `m2` 组；`vredsum` 的累加器与 `vtype` 组合细节**必须在 NEMU（或 spike）中跑通后再作为基线**。基线不正确会直接毁掉阶段三结论，故设门禁 G6（`03 §7`）。

## 5. 断言与检查点

| 类型 | 内容 | 实现 |
|---|---|---|
| Chisel 断言 | `vl==0 ⇒ !out.valid`；`out.bits[127:32]==0`；结果位宽不越界 | `assert()` in module（仅仿真） |
| 结构断言 | 输出恒为 `{96'b0, sext32(S)}` 形态 | 单元 TB 或 SVA 等价检查 |
| 协议断言 | 被 flush 的 uop 不得产生写回 | 框架既有检查 |
| 测试侧断言 | 每条用例检查**全 128 bit**，不只检查低 32 bit | 脚本强制 |

## 6. 覆盖率与收敛标准

| 覆盖类型 | 目标 | 手段 |
|---|---|---|
| 功能覆盖：符号组合 | 4 类（正/负、负/正、全负、全正）100% | 用例矩阵显式命中 |
| 功能覆盖：通道 | lane0..lane7 各自非零至少 1 次 | TC-B06 变体 |
| 功能覆盖：配置 | `vl∈{0,1,16}` × `vstart∈{0,1}` × `vm∈{0,1}` 全部组合 | 矩阵补全 |
| 功能覆盖：异常 | 3 类 illegal 各 1 次 | TC-E01..E03 |
| 代码覆盖（可选） | 行 ≥95%，分支 ≥90% | Verilator `--coverage`（若时间允许） |

**收敛判据**：所有 P0/P1 用例 100% 通过 + difftest 10k 随机 0 mismatch + 无未关闭的 S1/S2 缺陷。

| 级别 | 定义 | 响应 |
|---|---|---|
| S1 | 结果错误 / 无法编译 / 无法仿真 | 当日定位，阻塞其他工作优先修 |

**缺陷记录最小字段**：用例 ID、期望/实际（十六进制）、波形时间窗、uop 追踪、是否复现、修复提交号。

## 9. 性能测量方法学（阶段三核心）

### 9.1 指标定义（必须在报告中显式定义，避免歧义）

| 指标 | 定义 | 单位 |
|---|---|---|
| `L`（单条延迟） | 单条指令从发射（dispatch）到结果可被后继指令使用（WB 可见）的周期数 | cycle |
| `TP`（吞吐） | 无依赖背靠背序列的平均周期数/条 | cycle/inst |
| `N`（动态指令数） | 完成一次点积所需的动态指令条数（含 `vsetvli`） | inst |
| 加速比 | `L_base / L_vdot`，同时报告 `TP_base / TP_vdot` 与 `N_base / N_vdot` | × |

### 9.2 三种独立测量手段（交叉验证）

| 手段 | 做法 | 用途 | 陷阱 |
|---|---|---|---|
| M1 裸机计数 | `rdcycle`/`rdinstret` 包裹 N=1000 次循环，取 3 次中位数 | 主数据 | 循环开销、首次冷启动 → 先预热 100 次并扣除空循环基线 |
| M2 波形时间戳 | GTKWave 标注 uop 的 dispatch→WB 周期差，逐条统计 | 佐证 L 与 TP | 波形文件巨大 → 只截取 1 个稳定窗口 |
| M3 动态指令数 | NEMU/difftest 日志统计 `instret` 差值 | 佐证 N 与前端压力 | 需保证循环边界一致 |

### 9.3 测量协议（防"结论不可信"）

1. 同一二进制、同一 emu、同一配置下测 3 次，报告**中位数**与极差。
2. 两个模板同构：vdot 与 baseline 使用相同的循环骨架、相同的对齐、相同的退出条件，**唯一差异是指令序列**。
3. 起始条件一致：数据已在 `v1/v2` 中，不含加载指令（加载对两边等价，不应计入加速比）。
4. 明确报告"未计入"项：取指、访存、循环控制开销在两边相同，故不影响比值，但需在报告中说明。
5. 结论句式必须带限定："在本 emu 配置、本频率模型、无缓存影响下，单次点积延迟由 X 周期降至 Y 周期，加速 Z×"。

### 9.4 报告表格模板

| 配置 | L (cycle) | TP (cycle/inst) | N (inst) | 备注 |
|---|---|---|---|---|
| baseline（vsext×2 + vwmul + vredsum + 4×vsetvli） | 待测 | 待测 | 待测 | 3 次中位数 |
| vdot（单 uop） | 待测 | 待测 | 1 | 3 次中位数 |
| 加速比 | — | — | — | 附极差 |

### 9.5 面积代价（Should）

用综合或 Yosys 粗估 `VDot` 单元面积（相对既有 VFu 的百分比），给出"每单位面积换取的加速比"这一更有说服力的指标。若时间不足，退化为"乘法器数量 + 加法树级数"的结构性估算并明确标注为估算。

## 11. 测试风险与对策

| 风险 | 对策 |
|---|---|
| NEMU 建模工作量超预期 | 只实现"最小 vdot 语义"，不做通用化；用 Python 模型兜底比对 |
| 波形文件过大导致无法打开 | 只 dump 1000 周期窗口；先 `--dump-wave` 小规模试跑 |
| 基线序列在 RTL 上行为异常（vtype 组合） | 先在 NEMU 校验基线（G6），异常则改用更保守的 `vwmacc` 版本 |
| emu 构建慢导致迭代低效 | 用例批量化（一次构建跑全部），避免频繁重建；只在 RTL 改动后重建 |
| 测试期望写错（把 RTL 错误当正确） | 期望值只来自 Python 模型 + 手算闭式结论，禁止手填 RTL 输出 |
