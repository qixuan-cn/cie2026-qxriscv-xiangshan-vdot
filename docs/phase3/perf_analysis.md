# 阶段三 性能分析：Baseline 组合指令 vs vdot 专用加速单元

> **口径声明（必读）**
> 本文的性能数字分为两类，混用即视为错误：
> 1. **实测（Measured）**：仅"vdot 单元级吞吐/延迟"，来自 Verilator 仿真（3 cycle / 1.0 inst/cycle）。
> 2. **解析估算（Estimated）**：基线指令序列的指令数、uop 数与延迟，由指令语义 + 128 bit 数据通路假设推导，**未在香山或 NEMU 上运行**。
>
> 因此本文**不提供"实测加速比"**。表中所有加速比均为估算区间，需在阶段三环境就绪后按 §5 协议替换为实测值（对应测试报告 U-04）。

| 项 | 内容 |
|---|---|
| 基线功能等价性 | 已验证：1513/1513 条写回用例语义等价（`docs/phase3/00_baseline_equiv.log`） |
| 基线性能 | 估算（未运行） |
| vdot 单元级性能 | 实测（Verilator 5.034） |
| 加速比 | **估算区间**，不可作为最终结论 |

## 1. 基线定义（RISC-V 已有向量指令组合）

```asm
# int8 → int32 加宽，逐元素乘，再归约求和；结果与 vdot.vv 等价
vsetvli    t0, x0, e8, m1
vsext.vf2  v4, v1            # vs1: int8  -> int16 (m2)
vsext.vf2  v6, v2            # vs2: int8  -> int16 (m2)
vsetvli    t0, x0, e32, m4
vsext.vf2  v8,  v4           # int16 -> int32 (m4)
vsext.vf2  v12, v6
vmul.vv    v16, v8, v12      # SEW=32 逐元素乘
vsetvli    t0, x0, e32, m1
vredsum.vs v3, v16, v0       # 32 bit 求和（v0 预清零）
vmv.x.s    t1, v3
```

**为什么必须加宽到 32 bit**：`vredsum.vs` 的累加宽度等于目标 SEW，若停在 e16 则 8 项和在 `+131072` 处溢出（与 `ipd/01` §2.4 同一边界）。因此基线必须走 int8→int16→int32 两级加宽，这是它指令数偏多的直接原因。

**等价性验证**：`tests/ref_baseline.py` 在元素粒度模拟上述序列，对 1518 条向量中的 1513 条写回用例逐一比对，全部与 vdot 期望一致（`RESULT: PASS`）。这证明"基线确实算出同一个结果"，是性能对比有意义的前提。

> 待环境就绪后需复核：`vsext.vf2` 的 EMUL 约束（e16m2、e32m4）与 `vredsum.vs` 的 vd/vs2 宽度语义，必须在 NEMU 上跑通同样序列才算闭环（`ipd/02` 已列为风险）。

## 2. 工作量与 uop 数

假设 128 bit 数据通路：m1 = 1 beat、m2 = 2 beats、m4 = 4 beats；每 beat 1 uop。

| 指令 | SEW/LMUL | 数量 | 每指令 uop | 小计 uop |
|---|---|---|---|---|
| `vsext.vf2`（e8m1→e16m2） | 8→16 / m2 | 2 | 2 | 4 |
| `vsext.vf2`（e16m2→e32m4） | 16→32 / m4 | 2 | 4 | 8 |
| `vmul.vv`（e32m4） | 32 / m4 | 1 | 4 | 4 |
| `vredsum.vs`（e32m4） | 32 / m4 | 1 | 4 | 4 |
| **基线合计** | | **6** | | **20** |
| `vdot.vv` | 8 / m1 | **1** | **1** | **1** |

| 指标 | 基线（估） | vdot（实测/结构性） | 比值 |
|---|---|---|---|
| 计算指令数 | 6 | 1 | **6 : 1** |
| 含 vtype 切换的总指令数 | 9（+3 `vsetvli`） | 1（通常复用已设 vtype） | **9 : 1** |
| 向量 uop 数 | 20 | 1 | **20 : 1** |
| 写回带宽（每点积） | 4×128 bit + 标量 | 1×128 bit | **≈4 : 1** |
| 中间寄存器占用 | m2×2 + m4×3 | 无 | — |

## 3. 延迟模型（单次点积，估算）

依赖链为 `vsext → vsext → vmul → vredsum`（vs1 与 vs2 两条支路并行）。

```
lat ≈ Σ_{链上各指令} (uop 数 + L_pipe) + vtype 切换开销
    = (2 + 4 + 4 + 4) + 4 × L_pipe + Δvtype
```

| 参数 | 保守取值 | 说明 |
|---|---|---|
| `L_pipe` | 2–3 cycle | 单 uop 流水延迟假设，需用既有 `VAlu` 实测替换 |
| `Σ uop` | 14 | 链上 4 条指令的 beat 数 |
| `Δvtype` | 0–3 cycle | 3 次 `vsetvli` 的重配置开销，取决于实现 |

| 场景 | 基线延迟（估） | vdot 延迟（实测） | 估算加速比 |
|---|---|---|---|
| 乐观（L=2，Δvtype=0） | 22 cycle | 3 cycle | **≈7.3×** |
| 保守（L=3，Δvtype=3） | 35 cycle | 3 cycle | **≈11.7×** |

> 结论口径：**单次点积的延迟加速比估算区间约 7–12×**。`3 cycle` 是实测值，基线侧两个数字是估算，区间宽度来自 `L_pipe` 与 `vsetvli` 开销的不确定性。

## 4. 吞吐模型（批量点积，估算）

在向量发射端口 1 uop/cycle 的持续带宽下：

| 项 | 基线 | vdot |
|---|---|---|
| 每个 8 元素点积占用的发射槽 | 20 | 1 |
| 持续吞吐（上限） | 1/20 点积/cycle | 1 点积/cycle |
| 比值 | — | **≈20×（发射受限上限）** |

实际可持续吞吐还受：向量寄存器读端口（vdot 每周期读 2×128 bit）、写回端口（每周期 1×128 bit）、以及 vdot 与其它向量指令争用发射端口的影响。因此**工程预期取 10–20×**，而不是 20× 的上限。

**为什么 vdot 能到 1 条/周期**：乘法在 EX1、加法树在 EX2，两级各有独立硬件，不共享乘法器，也无跨 uop 归约；实测背靠背 1024 条无气泡（测试报告 §5）。

## 5. 面积与能效（generic 综合结果 + 定性推断）

> 阶段四已补 generic 综合（Yosys 0.52，工艺无关）：4186 个通用单元、172 个触发器、最长寄存器到寄存器路径 25 级，按 2 输入 NAND 等效口径约 **5.3k–8.4k GE（中值 ≈6.9k）**，详见 `docs/phase4/release_report.md` §3 与 `docs/phase4/01_yosys_synth.log`。下表首三行为结构事实，面积量级行已按综合结果更新。

| 项 | 结构 / 数值 | 依据 | 状态 |
|---|---|---|---|
| 乘法器 | 8 × 有符号 8×8 | 数据通路固定需求 | 结构确定 |
| 加法树 | 7 × 20 bit 加法器（3 级） | 8→4→2→1 | 结构确定 |
| 流水寄存器 | 8×16 bit + 20 bit + 控制位（共 172 FF） | 3 级流水 | 综合统计 |

## 8. 结论

1. **功能层面**：基线组合指令与 `vdot.vv` 结果等价（1513/1513 用例），性能对比成立。
2. **指令/uop 层面**：基线 6 条计算指令 / 20 个向量 uop，vdot 1 条 / 1 个 uop，减少 6×（指令）与 20×（uop）。
3. **延迟层面**：vdot 实测 3 cycle；基线估算 22–35 cycle；**估算加速比 7–12×**。
4. **吞吐层面**：vdot 实测 1 条/周期；基线受 20 uop 发射限制，**估算上限 20×，工程预期 10–20×**。
5. **诚实边界**：以上 2/3/4 中除 vdot 的 3 cycle 与 1 条/周期外**均为解析估算**，须按 §6 协议在香山/NEMU 上实测后替换。
